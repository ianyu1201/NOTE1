## 5. 当前产品基线

### 5.1 定位

NOTE1 是一个低压力、完全在本机运行的原生 iOS 灵感记录 App。核心主张是“简单记，快速看”。

### 5.2 两个产品亮点

1. **卡片流**：上下切换灵感、左滑收起、点击完整编辑、归入构思集；
2. **小票册**：一轮构思结束后生成固定构思小票，并以小票册保存阶段成果。

不得为了简化导航弱化卡片流，也不得把小票册改成普通文件列表。

### 5.3 当前闭环

```text
记录灵感
→ 在灵感时间流查看
→ 进入卡片预览快速回看
→ 收起或归入构思集
→ 在构思集继续编辑和组织
→ 结束本轮构思
→ 生成不可变构思小票
→ 在小票册浏览、导出、分享或删除
```

### 5.4 关键限制

- 最多 5 个构思集；
- 每个构思集最多 10 条灵感；
- 一条灵感同一时间只能属于一个构思集；
- 独立灵感左滑是“收起”，不是删除；
- 构思集结束一轮后生成一张新小票；旧小票不被覆盖；
- 回收站保留灵感 30 天；
- 小票快照不随源灵感或附件后续变化而修改。

### 5.5 明确排除

- 登录和账号；
- 云同步和后端；
- AI；
- 标签体系；
- 任务管理；
- Web、桌面或 Android 客户端；
- V0.1 测试数据迁移承诺。

## 6. 当前实现状态与问题

### 6.1 已实现

- 四个一级页面和边缘横滑；
- 文字、照片、文件和两类语音录入；
- 卡片预览、完整编辑、收起、撤回和归入构思集；
- 构思集总页、工作台、结束本轮和继续构思；
- 构思小票生成、经典票/胶卷票、小票册、详情、查找、导出与分享；
- 全局搜索、批量选择、设置、备份恢复和回收站；
- 本机事务、附件资源和不可变小票快照；
- 领域与 UI 策略自动化测试。

### 6.2 已知工程问题

1. 附件预览/图标存在重复标识风险；
2. 大备份与恢复可能阻塞主线程；
3. V0.1 与 V0.2 双实现同时编译，需要审计后再决定隔离或删除；
4. 高频完整状态保存需要性能测量；
5. 真机 VoiceOver、文件提供器权限、中文键盘、分享最终投递和 iOS 17–25 材质降级仍有手工证据缺口。

详细内容见 `NOTE1_V0.2源码审查与V0.2.1稳定化建议.md`。

### 6.3 已知 UI 审查结论

- 灵感首页：品牌成立，信息密度失衡；
- 构思集工作台：核心结构成立，底部操作过密；
- 全局页面在按钮比例、材质亮度、标题位置、浮动按钮与底栏关系上仍需产品化；
- 当前版本可作为功能测试基线，但不能直接视为最终产品 UI。

详细内容见 `NOTE1_V0.3产品设计优化建议.md` 与 V0.2 UI ISSUE。

## 8. V0.3 开发会话协作规则

开发会话可以使用多个子智能体，但需遵守：

- 主开发会话拥有总体计划、合并、冲突处理和最终验证责任；
- 子智能体只接受范围明确的独立任务；
- 每个子智能体明确文件所有权，不得覆盖他人改动；
- 产品或架构决策不委派给执行型子智能体；
- 先数据与状态，再组件，再页面，再整包验证；
- 每个垂直切片完成测试、证据和提交后再进入下一项；
- 实现者不能单独宣布产品验收通过；
- 新需求返回产品会话确认，不在开发中自行扩张。
