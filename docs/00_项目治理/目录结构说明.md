# NOTE1 目录结构说明

> 状态：现役目录治理规则
> 更新日期：2026-08-08

## 当前阶段

NOTE1 当前处于 V0.3 产品与设计阶段。V0.3 尚未冻结最终视觉，也未授权业务代码开发。固定提交 `b403277d61335eaf1ea0c930faca338686624d8c` 是现状起点，不自动覆盖用户确认的 V0.3 目标。

## 顶层职责

```text
NOTE1/
├── AGENTS.md       项目规则、标准术语和安全边界
├── README.md       仓库与运行入口
├── ios/            正式 Xcode 工程、Swift 源码与测试
├── docs/           三份现役基线、治理状态与 ADR
├── evidence/       截图、录屏、日志和对照板
└── media/          V0.1 历史真实运行证据
```

`ios/` 和 `media/` 是工程或证据索引直接使用的目录，不因文档整理随意改名。

## 文档分层

- `00_项目治理/`：项目状态、任务登记和目录规则，不定义产品需求。
- `01_产品/V0.3/`：唯一现役完整 PRD。
- `02_设计/V0.3/`：唯一现役产品设计与交互规格。
- `03_工程/V0.3/`：唯一现役开发、非回归和运行验收基线。
- `04_技术决策/`：ADR；改变已接受决策时新增或取代 ADR，不删除历史 ADR。

旧版本文档不在仓库中保留重复副本，需要追溯时使用 Git 历史、版本标签、`media/` 和 `evidence/`。

## 证据分层

- `evidence/<版本>/`：按原验收批次保存真实运行截图、录屏、日志和索引。
- `evidence/references/`：开发参考图，只约束明确写入索引的对象关系。
- 产品确认视觉必须在 V0.3 设计规格中登记目标和状态，不能与运行证据混用。
- 未确认或已否决视觉不作为开发目标；无继续参考价值时删除，由 Git 历史追溯。

## 新文件放置规则

1. 产品决定直接更新 `01_产品/V0.3/NOTE1_PRD_V0.3.md`，不新增并行 PRD。
2. 页面、视觉和交互决定直接更新 `02_设计/V0.3/NOTE1_V0.3产品设计与交互规格.md`，不新增并行建议稿。
3. 开发约束、非回归、ISSUE 风险和验收合同直接更新 `03_工程/V0.3/NOTE1_V0.3开发与运行验收基线.md`，不新增并行清单。
4. 任务状态只写入 `PROJECT_STATE.md` 和 `THREAD_REGISTRY.md`，完成后依靠 Git 提交保留历史。
5. 新截图、录屏和日志进入 `evidence/<版本>/<批次>/`，同时更新该批次索引。
6. 不在仓库根目录新增一次性计划、临时截图、构建缓存或旧副本。

## 移动与删除门禁

- 移动文档后必须更新 Markdown、AGENTS、README 和证据索引中的全部引用。
- 移动源码前必须核对 Xcode target 文件归属；本轮目录治理不移动源码。
- 删除或重命名证据、产品对象或代码目录前必须取得用户授权；已被完整吸收的重复文档可在授权后删除并由 Git 历史追溯。
- 每次目录调整至少通过相对链接检查、Git 状态检查和相关工程配置检查。
