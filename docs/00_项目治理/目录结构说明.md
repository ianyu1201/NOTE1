# NOTE1 目录结构说明

> 状态：现役目录治理规则
> 更新日期：2026-08-03

## 当前阶段

NOTE1 当前处于 V0.3 产品与设计阶段。V0.3 尚未冻结新视觉，也未授权业务代码开发。V0.2 代码是功能与工程起点，不是 V0.3 最终 UI。

## 顶层职责

```text
NOTE1/
├── AGENTS.md       项目规则、标准术语和安全边界
├── README.md       仓库与运行入口
├── ios/            正式 Xcode 工程、Swift 源码与测试
├── docs/           权威文档与历史文档
├── evidence/       截图、录屏、日志和对照板
├── media/          被推广资料引用的历史真实运行素材
└── video/          独立宣传视频工程（当前由用户另行处理）
```

`ios/`、`media/` 和 `video/` 是工具或代码直接使用的目录，不因文档整理随意改名。

## 文档分层

- `00_项目治理/`：入口、交接和协作流程。
- `01_产品/<版本>/`：PRD、产品边界、产品方向和待讨论项。
- `02_设计/<版本>/`：设计规格、确认视觉、候选视觉和设计探索。
- `03_工程/<版本>/`：现役工程规范、非回归门禁、ISSUE 和源码风险。
- `04_技术决策/`：ADR；改变已接受决策时新增或取代 ADR，不删除历史 ADR。
- `90_历史归档/<版本>/`：已执行任务单、过程计划和旧审计，不再作为现役指令。

## 证据分层

- `evidence/<版本>/`：按原验收批次保存真实运行截图、录屏、日志和索引。
- `evidence/references/`：开发参考图，只约束明确写入索引的对象关系。
- 产品确认视觉继续保存在 `docs/02_设计/<版本>/视觉基线/`，不能与运行证据混用。
- 未确认或已否决视觉保存在 `docs/02_设计/<版本>/视觉候选/`，不能作为开发目标。

## 新文件放置规则

1. 新 PRD 或范围决定进入 `01_产品/<版本>/`。
2. 新视觉、状态图或交互规格进入 `02_设计/<版本>/`。
3. 新开发准则、ISSUE 或非回归门禁进入 `03_工程/<版本>/`。
4. 单次实施任务完成后移入 `90_历史归档/<版本>/`，不与现役规范平铺。
5. 新截图、录屏和日志进入 `evidence/<版本>/<批次>/`，同时更新该批次索引。
6. 推广内容继续进入 `docs/推广资料/`；它不参与产品事实裁决。
7. 不在仓库根目录新增一次性计划、临时截图、构建缓存或旧副本。

## 移动与删除门禁

- 移动文档后必须更新 Markdown、AGENTS、README 和证据索引中的全部引用。
- 移动源码前必须核对 Xcode target 文件归属；本轮目录治理不移动源码。
- 删除或重命名历史证据、产品对象或代码目录前必须取得用户授权。
- 每次目录调整至少通过相对链接检查、Git 状态检查和相关工程配置检查。
