> 适用项目：NOTE1 原生 iOS App

## 1. 文档定位

本目录不是新的产品基线，也不替代 V0.1、V0.2 已确认文档。它用于把 V0.2 的真实结果、V0.3 值得保留的优化方向、工程风险和协作方式整理成下一阶段可执行的参考包。

V0.3 开发前仍须遵循以下优先级：

1. `docs/产品文档/NOTE1_PRD_V2.6.md`：V0.1 已实现与验收事实。
2. `docs/产品文档/NOTE1_PRD_V0.2.md`：V0.2 已确认增量产品基线。
3. `docs/产品文档/NOTE1_V0.2_产品设计与交互规格.md`：现行页面、手势、动效和视觉确认。
4. `docs/开发文档/NOTE1_V0.1到V0.2能力非回归矩阵.md`：不可丢失的旧能力。
5. 本目录：V0.3 的复盘、候选方向、稳定化和交付方法。

当本目录与上述现役基线冲突时，以现役基线和用户最新明确确认的口径为准。

## 2. 当前统一结论

### 2.1 已确认事实

- NOTE1 继续定位为低压力、完全在本机运行的原生 iOS 灵感记录 App。
- 产品主张继续是“简单记，快速看”，不扩张为任务管理、知识库或全平台笔记工具。
- V0.3 起点保留四个一级入口：`灵感｜卡片预览｜构思集｜小票册`。
- 卡片流是第一核心体验；构思小票和小票册是第二核心辨识度。
- V0.2 分支已形成可运行的功能闭环和自动化基础，但尚不能等同于正式封版或最终产品品质。
- V0.3 的第一目标不是增加功能，而是把现有闭环做到统一、美观、顺滑、可信。

### 2.2 明确不采纳

- 不把四个一级入口压缩为三个入口。
- 不把卡片预览合并进灵感首页。
- 不取消一级页面的全面屏横向切换。
- 不把卡片流手势降级为普通点击列表。
- 不引入登录、云同步、AI、标签、任务管理或桌面端。
- 不把未经用户确认的目标用户、市场判断或量化指标写成既定事实。

## 4. 建议阅读顺序

1. 新产品会话先读《V0.3 产品会话交接与启动说明》，按其中协议完成全仓阅读。
2. 再读 V0.1、V0.2 现役基线和非回归矩阵。
3. 读产品复盘，确认 V0.3 的问题、边界和成功定义。
4. 读产品设计优化建议，产出四个核心页面的视觉与交互确认稿。
5. 读源码审查，先关闭会影响数据和稳定性的工程问题。
6. 读协作交付方案，按固定提交、固定范围和独立验收推进开发。

## 5. V0.3 开发准备状态

当前文档包可以支持：

- V0.3 设计任务拆解；
- 交互原型与视觉确认稿制作；
- V0.2.1 稳定化实施；
- V0.3 垂直切片开发任务编写。

正式开始大范围 UI 代码改造前，仍须完成以下门禁：

- [ ] 四个一级页面的默认态、空态、内容态和关键操作态均有确认图或可运行原型。
- [ ] 卡片预览手势、构思集归入、小票生成与小票册浏览有完整状态图。
- [ ] 每张确认图已映射到验收场景，而不是只作为气氛参考。
- [ ] V0.1 非回归矩阵中相关能力已写进任务验收条件。
- [ ] 开发任务固定到明确 Git 提交，并划定允许修改的文件范围。

未通过这些门禁时，可以继续设计和稳定化，但不能宣称 V0.3 已具备整包开发条件。

## 6. 从乔布斯审视中保留的有效原则

只保留适合 NOTE1 的方法，不把人物判断当作产品事实：

1. **聚焦**：V0.3 先把现有闭环做好，不增加新产品线。
2. **端到端体验**：功能、手势、视觉、数据安全和真机表现必须共同验收。
3. **看不见的品质**：附件、备份、恢复、性能和无障碍不能因 UI 优化而退化。
4. **一句话清晰**：所有页面和功能都应服务“简单记，快速看”。
5. **独立验收**：实现者不能只凭自己的截图宣布完成。
