# NOTE1 V0.3 产品设计优化建议

> 状态：V0.3 设计实施参考  
> 更新日期：2026-08-03  
> 前置条件：必须同时阅读 V0.2 PRD、产品设计与交互规格、视觉确认图和非回归矩阵

## 0. 文档职责与证据边界

本文负责定义 V0.3 的设计优化原则、页面职责、交互非回归要求、视觉交付物和设计验收门禁。它不是新的像素级确认稿，也不授权开发者凭文字自行补全视觉。

设计实施时的证据优先级：

1. 用户最新明确确认的页面图与交互状态图；
2. `NOTE1_V0.2_产品设计与交互规格.md`；
3. V0.1/V0.2 非回归矩阵；
4. 本文的设计治理规则；
5. 外部开源参考仅作为材质、动效或实现方法参考，不作为产品事实。

## 1. 总体设计结论

V0.3 不重做 NOTE1 的产品结构，而是对现有结构进行产品化：

- 保留四个一级页面；
- 保留卡片流核心手势；
- 保留构思集与小票闭环；
- 统一页面框架、视觉变量、按钮、材质、动效和安全区；
- 用完整状态和真机证据消除“功能能用但不像最终产品”的问题。

V0.3 的视觉目标不是“更炫”，而是：安静、轻盈、清楚、有触感，不产生压力，不带模板化的 AI UI 痕迹。

## 2. 信息架构非回归基线

### 2.1 四个一级页面

固定顺序为：

`灵感｜卡片预览｜构思集｜小票册`

- 四个入口地位平等，底部导航命中区域满足 iOS 可触达要求。
- 一级页面支持固定顺序的边缘横滑切换，不循环。
- 页面内对象手势优先；达到明确方向和距离后才接管一级页面切换。
- 浮动新增按钮只出现在灵感、卡片预览、构思集；小票册不显示新增按钮。
- 浮动按钮覆盖在内容层之上，页面不得为它预留大块空白；同时必须避开底部导航和 Home Indicator。

### 2.2 顶部框架

- 灵感页：左侧统一入口，中间 NOTE1 及排序入口，右侧搜索。
- 卡片预览：标题与主要导航位置保持稳定，避免因卡片内容改变而跳动。
- 构思集、小票册：名称居中；页面级搜索或更多操作按已确认状态图呈现。
- 同类按钮在不同页面保持位置、尺寸、材质和按压反馈一致。

不得因“简化”擅自把卡片预览并入灵感页，也不得将四入口压缩成三入口。

## 3. 四个核心页面

### 3.1 灵感页

#### UI 审查结论：品牌成立，信息密度失衡

**成立的部分：**

- NOTE1 居中品牌标识、冷调浅紫背景和深海军蓝图标已经形成可识别的视觉方向；
- 灵感时间流与底部快速录入符合“简单记”的产品目标。

**当前问题：**

- 顶部区域、周度摘要、灵感条目、浮动新增按钮和底部导航同时争夺注意力；
- 灵感条目使用相近的大块浅色容器，信息层级被卡片外形取代，首屏可读内容偏少；
- 品牌区域留白与内容密度缺少过渡，容易形成“上方松、下方挤”的视觉节奏；
- 内容数量增加后，底部导航和浮动按钮可能覆盖最后一条灵感。

**优化要求：**

- 保留现有品牌识别，不用缩小或隐藏 NOTE1 来解决密度问题；
- 减少无层级意义的卡片底板，让正文、时间、归属和附件状态形成清楚的信息层级；
- 周度摘要保持次要，不得比最近灵感更醒目；
- 统一顶部栏、时间流、浮动新增按钮和底部导航的垂直节奏；
- 内容滚动区必须包含正确安全区，不依赖额外空白规避悬浮控件。

**验收标准：**

- [ ] 用户第一眼仍能识别 NOTE1 品牌和当前页面；
- [ ] 首屏重点依次为快速记录入口、最近灵感、次要摘要，不发生层级倒置；
- [ ] 灵感内容增加到可滚动状态后，最后一条仍可完整阅读和点击；
- [ ] 默认字号与最大辅助字号下，顶部和底部均无覆盖、截断或异常空白；
- [ ] 页面不再依赖连续的大白卡区分每条灵感。

#### 页面职责

- 用户打开 App 后最快完成记录；
- 按时间查看全部独立灵感；
- 提供全局搜索入口；
- 呈现克制的使用反馈，不抢占记录主路径。

#### 设计要求

- 顶部按钮、NOTE1 标识和排序箭头在同一视觉基线；排序入口不应下沉或与品牌字标割裂。
- 时间流以内容为主，避免每条灵感都成为厚重、过白、相互独立的“大卡片”。
- 底部新增面板与键盘自然衔接，支持多行文字、语音灵感、照片和文件附件。
- 输入面板展开后必须可收起；键盘出现时不得遮挡发送、附件或关闭入口。
- 搜索进入后，搜索框位于顶部，筛选和结果层级清楚，返回路径简单。
- 选择功能从统一入口进入，不在主页常驻并抢占标题空间。

#### 不得丢失

- 文本、照片、文件和两种语音模式；
- 附件预览与删除；
- 搜索与历史数据访问；
- 中文输入、复制粘贴及系统菜单本地化；
- 首页不可因键盘或内容高度出现异常底部空白。

### 3.2 卡片预览

#### 页面职责

卡片预览是 NOTE1 的第一核心体验，用于快速重新遇见灵感，而不是普通详情列表。

#### 核心手势

- 上下滑：像短视频信息流一样切换前后卡片；前后卡片可露出少量边缘，提供空间连续性。
- 左滑：越过阈值后将独立灵感“收起”；轻微横移只显示克制反馈，不提前触发完成感。
- 从屏幕左边缘向右滑：返回上一层或灵感页，不与左滑收起混淆。
- 点击卡片：进入完整编辑页，保留附件、预览和完成编辑能力，不使用缺功能的临时弹窗替代。

#### 构思集入口

- 卡片下方保留稳定的“归入构思集”按钮，位置高于底部导航且不被遮挡。
- 长按后只出现与当前状态匹配的两个拓展目标：`新建构思集`、`归入现有构思集`。
- 拓展目标采用轻微倾斜、柔和悬浮的视觉，不使用弧线连接。
- 用户只拖拽一次：长按按钮并移动到目标，松手后再以点击列表选择具体构思集。
- 已有 5 个构思集时不显示“新建构思集”；没有构思集时只显示“新建构思集”。
- 目标构思集达到 10 条时拒绝归入，并提示“当前版本每个构思集只支持 10 条灵感”。

#### 动效要求

- 上下切换必须连续，不得突然替换内容或跳回首卡。
- 左滑收起应有阻尼、阈值、离场和下一卡承接；撤回提示不能阻塞继续滑动。
- 按压态只轻微降低亮度或增加材质密度，默认态保持原有浅色主题，不变灰、不刺眼。
- 减少动态效果开启后，仍保留状态变化但降低位移和弹性。

### 3.3 构思集

#### 总页面

- 页面名称居中；右下角显示悬浮新增按钮。
- 最多 5 个构思集；未达到上限时点击新增直接进入创建流程。
- 达到上限后点击新增，显示小型提示：“当前版本只支持 5 个构思集”。
- 提示只由真实上限状态触发，不得在空态或未满时出现。
- 构思集使用轻量卡片或纸张堆叠表达，但避免过亮白块和厚重阴影。

#### 单个构思集工作台

##### UI 审查结论：核心结构成立，底部操作过密

**成立的部分：**

- 卡片式工作台、前后卡片少量露出和上下切换延续了 NOTE1 的卡片流语言；
- 用户能够围绕同一构思集反复切换、编辑和补充灵感，符合“继续构思”的目标。

**当前问题：**

- 附件、移出、更多、前后切换、新增、完成编辑和结束本轮等操作可能集中在屏幕底部；
- 键盘出现后，可操作空间进一步压缩，主要操作与低频管理操作难以区分；
- 页面级新增按钮若在编辑态继续存在，会和当前卡片操作重复；
- 底部控件过多会遮挡卡片内容，并削弱卡片本身的视觉中心。

**优化要求：**

- 底部只保留当前场景最高频、最直接的操作；
- 低频管理操作收入口明确的“更多”菜单或次级面板，但不得隐藏用户完成核心闭环所必需的入口；
- 浏览态、编辑态和键盘态分别定义操作栏，不使用同一套控件强行覆盖所有状态；
- 编辑态删除重复的页面级新增按钮；
- “结束本轮构思”保持构思集级语义，与当前卡片的编辑完成、移出和附件操作分层；
- 最终按钮位置和组合以工作台状态图为准，开发者不得自行增加一排临时按钮。

**验收标准：**

- [ ] 浏览态、编辑态和键盘态均能明确指出唯一主操作；
- [ ] 键盘出现时附件与完成编辑入口可达，且不遮挡正文输入区域；
- [ ] 页面级新增按钮不会在编辑态重复出现；
- [ ] 低频操作可在两步以内找到，返回后保持当前卡片和编辑位置；
- [ ] 默认字号和最大辅助字号下，底部操作不重叠、不越过安全区；
- [ ] 工作台卡片仍是页面视觉主体，底部工具区不形成独立的大块模块。

- 以可上下切换的卡片方式继续构思，保留前后卡片少量露出。
- 支持在卡片之间反复切换、编辑、调整顺序、移出和新增灵感。
- 每个构思集最多 10 条；达到上限时新增入口仍可见，但点击后提示容量限制。
- 编辑状态的“完成”与附件操作同一操作层级，键盘出现时不被遮挡。
- 编辑状态不重复显示页面级新增按钮。
- “结束本轮构思”是构思集级操作，不等同于删除或收起单卡。

#### 结束本轮

- 越过确认阈值后先出现确认，不直接生成小票。
- 确认文案说明本轮将结束并自动生成构思小票；取消则回到原状态。
- 完成后允许约 2 秒撤回；撤回提示不能阻塞其他必要操作。

### 3.4 小票册与构思小票

#### 小票册职责

小票册保存每一轮构思的固定成果，是 NOTE1 的第二核心体验，不是普通文件列表。

#### 页面要求

- 页面名称居中，右上角使用“更多”三点按钮；不显示右下角新增按钮。
- “更多”承载搜索、选择、导出、分享和删除等页面级功能，避免将一排工具固定在小票下方。
- 小票以完整长条比例呈现，可左右切换；下拉抽取进入完整详情。
- 预览应让用户看出模板、主要内容、照片和时间，不得只显示短小截断片段。
- 经典票适合文字和数字；胶卷票适合多照片。模板由内容规则推荐，用户可切换。

#### 生成与浏览动效

- 构思集结束后，小票从生成到进入小票册必须有完整过渡，不突然弹出成品。
- 生成动效可参考现有确认的打印小票动效，但需转化为 SwiftUI 可维护实现。
- 左右切换采用柔和堆叠和物理阻尼；下拉抽取强调纸张被取出的纵深感。
- 动效不可阻塞返回、下一张浏览或辅助功能。

#### 快照规则

- 小票生成后固定不变；继续构思生成新小票，不覆盖旧小票。
- 原灵感或附件后续变化，不反向修改旧小票快照。
- 删除小票不影响构思集；删除源附件后旧小票仍保留生成时快照。

## 4. 全局交互规则

### 4.1 手势与按钮的关系

NOTE1 以手势形成效率和特色，但关键能力必须有等价按钮或辅助功能入口：

- 卡片上下切换、左滑收起是主体验；
- 返回、收起、归入构思集、结束本轮等关键结果必须可被 VoiceOver 操作；
- 不要求用户记住隐藏手势才能找回或管理数据。

### 4.2 手势冲突优先级

1. 编辑文本、附件预览和系统返回手势；
2. 当前对象手势，如卡片上下切换或左滑收起；
3. 一级页面边缘横滑；
4. 普通滚动。

实现时需要方向锁、起始边缘、距离阈值和速度阈值。轻微斜滑不得误触收起或切页。

### 4.3 反馈规则

- 触发前：轻量、克制，仅提示可操作方向；
- 越过阈值：状态明确，但不使用大面积高饱和遮罩；
- 成功后：有短促正反馈和可撤回；
- 失败时：提示原因并保持当前数据和位置；
- 所有提示不得长期覆盖内容或阻塞后续手势。

## 5. 视觉系统治理

### 5.1 保留的气质

- 冷调浅紫背景；
- 深海军蓝文字与图标；
- 低对比半透明材质；
- 柔和纸张、玻璃和光影层次；
- 大面积安静留白，但留白必须服务内容和操作。

### 5.2 必须减少

- 纯白高亮按钮和过强发光；
- 同一页面同时出现过多圆角胶囊；
- 没有层级意义的灰色底块；
- 为浮动按钮预留的无内容空区；
- 模板化“大标题 + 大白卡 + 大圆按钮”的 AI UI 组合；
- 使用随机阴影和不同透明度假装层级。

### 5.3 必须统一

设计变量集中管理并覆盖：

- 背景色、正文色、次级文字色、强调色；
- 玻璃/纸张/浮层三类材质；
- 圆角、边框、阴影、模糊；
- 标题、正文、时间和辅助文字字号；
- 顶部栏、底部导航、浮动按钮和常规按钮尺寸；
- 按压、选中、禁用、拖入和错误状态；
- 动效时长、弹性、阻尼和减少动态效果降级。

默认态不能因“降低亮度”而整体发灰；调整重点是按压态和选中态。

## 6. 无障碍与系统适配

- 最低 iOS 17；最新系统材质可增强，但旧系统必须有稳定磨砂降级。
- 支持动态字体，核心布局在常规字号和最大辅助字号不截断关键操作。
- 每个图标按钮提供中文可访问名称、提示和必要状态。
- VoiceOver 顺序符合视觉顺序；卡片手势提供自定义辅助操作。
- 对比度不能依赖极浅灰文字；选中状态不能只依赖颜色。
- 减少动态效果开启后，页面仍可理解且操作结果一致。
- 中文键盘、英文键盘、硬件键盘和粘贴菜单均需真机检查。

## 7. 设计阶段必须交付的内容

### 7.1 四页总览

为四个一级页面提供同一设备、同一比例的总览图，确认顶部框架、内容区域、浮动按钮和底部导航关系。

### 7.2 页面状态矩阵

每个页面至少覆盖：

- 默认态；
- 空态；
- 内容态；
- 加载或处理中；
- 错误或容量上限；
- 搜索或选择态（适用页面）；
- 键盘态（适用页面）；
- 动态字体与 VoiceOver 关键态。

### 7.3 核心交互状态图

必须单独交付：

1. 卡片上下切换；
2. 卡片左滑收起与撤回；
3. 归入构思集的长按、拖入目标、松手和列表选择；
4. 构思集工作台切换与编辑；
5. 结束本轮确认、生成小票和撤回；
6. 小票册左右切换、下拉抽取和详情返回。

### 7.4 组件与变量清单

- 顶部栏；
- 底部导航；
- 浮动新增按钮；
- 图标圆按钮；
- 卡片与纸张；
- 输入面板；
- 搜索和筛选；
- 选择与批量操作；
- Toast、确认框和容量提示；
- 小票预览与详情。

每个组件给出默认、按压、选中、禁用和错误状态。

### 7.5 验收映射

每张确认图必须记录：

- 页面和状态名称；
- 对应需求编号；
- 参考图文件路径；
- 需要验证的交互；
- 允许的系统差异；
- 不可接受的偏差。

## 8. 设计关闭标准

V0.3 UI 开发开始前，以下项目必须全部满足：

- [ ] 四页总览得到用户确认。
- [ ] 六组核心交互状态图得到用户确认。
- [ ] 视觉变量与组件状态完整。
- [ ] 所有 V0.1 非回归能力有对应设计入口。
