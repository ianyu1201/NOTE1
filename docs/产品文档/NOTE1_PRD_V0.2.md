## 0. 文档目的

V0.2 在保持 NOTE1“快速记录、低压力预览、继续思考”的主定位下，逐项收口下一阶段的产品方向。

本文件采用三种状态：

- **已确认**：作为 V0.2 设计、开发和测试基线。
- **开发默认值**：已经有可实现行为，可以先开发；后续只调整参数或视觉，不改变核心语义。
- **不在本轮**：明确不因当前讨论引入的能力；统一进入待讨论清单或未来版本。

V0.2 应先完成整体产品范围与交互闭环，再形成开发交接；不得以“单个模块已确认”为由逐项扩张或抢先实现未收口内容。

### 0.1 V0.2 产品定位

NOTE1 继续坚持“简单记，快速看”，只服务原生 iPhone 场景。用户产生灵感时，可以低摩擦地记录文字、可播放的语音灵感、照片或文件；也可以把会议录音、音乐等音频作为附件保存。稍后通过卡片预览重新进入当时的思考。

NOTE1 不以帮助用户长期囤积更多笔记为核心，也不复制 flomo 的标签体系、全库知识管理、日历统计、跨端积累或 AI 关联检索。用户可以自行把 NOTE1 长期使用为记录工具，但产品资源优先投入以下短周期闭环：

```text
记录 → 预览 → 选择仍有价值的灵感 → 进入构思集
→ 在几张卡片之间反复推演 → 结束本轮构思
→ 生成构思小票 → 保存、分享或带到其他工具继续开发
```

V0.2 的差异化不在于“比其他笔记软件存得更多”，而在于帮助用户把仍有温度的零散灵感，在一天或一周等较短周期内重新激发、看清关系、形成一份可见存根，并低摩擦地交给备忘录、Obsidian、Codex 或其他工具。

### 0.2 产品体验目标

- **记录时轻量**：打开手机即可记，不要求先分类、选择项目或整理结构。
- **构思时重新激发**：用户在最多 10 张有关联的卡片之间反复切换、补充和调整顺序，重新找到当时的语境。
- **构思时逐渐清楚**：工作台帮助用户看见几条思考之间的先后和联系，但不替用户自动下结论。
- **结束时获得成就感**：结束本轮构思后，系统把完整过程收束为一张构思小票；成就感来自“零散灵感已经形成可带走的成果”，而不是积分、排名、打卡或效率评分。

V0.2 的两项核心产品亮点已经明确：

1. **卡片流**：通过符合全面屏习惯的纵向滑动重新浏览灵感，让“快速看”成为 NOTE1 最直接的使用体验。
2. **构思小票与小票册**：把一次构思中易消散的时间、内容变化和灵感关系保存为可见成果，让用户感受到本轮思考确实留下了东西。

后续视觉与交互资源应优先打磨这两项能力。小票册不只是归档列表，而是 NOTE1 展示构思成果、积累成就感和形成产品辨识度的核心空间。

### 0.3 NOTE1 专有名词标准

以下名称是 V0.1、V0.2、代码、测试、设计和后续讨论共同使用的项目标准。用户口述“灵感组、想法组、卡片组或推进组”等旧称时，应结合语境自动识别为标准名称，不要求用户重新表述。

| 标准名称 | 定义 | 旧称或易混名称 |
| --- | --- | --- |
| 灵感 | 用户保存的一条独立内容，可包含文字和附件 | 想法、笔记、独立记录 |
| 卡片 | 灵感在卡片预览中的视觉呈现，不是另一种数据对象 | 灵感卡片 |
| 卡片预览 | 用户集中翻阅灵感的功能 | 回看、卡片回看 |
| 卡片流 | 当前可以上下切换的卡片集合 | 回看流 |
| 全部灵感 | 只浏览和管理全部独立灵感的页面内容；V0.2 底部标签简写为“灵感”，不混入构思集或构思小票 | 首页、历史、历史记录 |
| 收起 | 将独立灵感移出卡片流，但不删除本机记录 | 完成 |
| 已收起 | 独立灵感当前不参与卡片预览 | 已完成 |
| 放回卡片流 | 将已收起灵感重新加入卡片流 | 恢复、放回回看、放回预览 |
| 构思集 | 用户正在集中构思的一组灵感 | 灵感组、想法组、卡片组、推进组 |
| 归入构思集 | 将一条灵感加入一个构思集 | 加入组、归入推进组 |
| 构思中 | 构思集当前仍可编辑、排序和补充 | 未完成、推进中 |
| 结束本轮构思 | 结束当前构思过程并准备生成小票 | 完成组、结束本轮 |
| 已结束 | 当前构思轮次已经结束 | 已完成、已归拢 |
| 继续构思 | 从已结束构思集或旧小票开启新一轮 | 恢复组、继续推进 |
| 构思轮次 | 从开始构思到结束本轮之间的一段过程，主要用于 PRD 和数据模型 | 推进轮次 |
| 构思历程 | 保存并查看已结束构思集及其历次构思轮次关系的空间 | 过往、历史、历史构思 |
| 构思小票 | 一轮构思结束后生成的固定成果 | 推进小票、整理稿 |
| 小票册 | 保存全部构思小票的区域 | 小票夹、小票仓库 |
| 经典票 | 适合文字、数字和少量图片的构思小票模板 | 文字票 |
| 胶卷票 | 适合照片、绘画和视觉素材的构思小票模板 | 胶片票 |
| 语音灵感 | 用户在录入面板中直接录制的一段可播放声音；保存后仍是一条普通灵感，可同时保留可编辑转写文字 | 语音录入、口述灵感 |
| 音频附件 | 用户从附件入口加入的已有音频文件，用于保存会议录音、音乐等声音资料 | 语音附件、录音附件 |

标准结束反馈为：

> 本轮构思已结束，N 条灵感已收录。

### 0.4 核心对象与状态口径

V0.2 使用以下对象关系，后续章节不得混用“构思集”“构思轮次”“构思小票”和“灵感”：

| 对象 | 状态或关系 | 主要入口与呈现 | 关键规则 |
| --- | --- | --- | --- |
| 灵感 | 预览关系：独立在卡片流 / 由构思集代表 / 已收起；构思集关系：未归集 / 属于某个构思集 | 底部“灵感”一级页面、卡片预览和搜索 | 始终是独立本机记录；归入构思集后仍可在全部灵感中单独找到 |
| 构思集 | 构思中；可包含已经结束的构思轮次 | 底部“构思集”一级页面、卡片预览快速归入面板和工作台 | 同时最多 5 个构思中的构思集；每组最多 10 条灵感；一张灵感同一时间最多属于 1 个构思集 |
| 构思轮次 | 构思中 / 已结束 | 工作台；结束后进入所属构思集的构思历程 | 同一构思集可以有多轮；用户左滑或点按结束操作后，每次只结束当前轮次 |
| 构思小票 | 已保存的轮次存根 | 底部“小票册”一级页面；也可从来源构思轮次进入 | 一轮严格对应一票；内容与附件快照固定，展示模板可以切换 |

“卡片如何参与卡片预览”和“灵感是否属于构思集”是两个独立维度，不应压缩成一个“完成 / 未完成”状态。灵感因归入构思集而不再独立显示，不等于用户对它执行了“收起”。

## 1. 已确认方向：构思集

### 1.1 定义与目的

原“灵感组”在 V0.2 中调整为“构思集”。

构思集不是长期知识分类目录，也不是任务看板；它表示用户正在继续思考的一条有限思考线。用户可以把普通卡片主动归入构思集，在需要时集中回到这几张有关联、仍有温度的卡片。

NOTE1 允许用户把构思集用于轻量待办、长期事件或其他个人场景，但产品本身不为此加入截止日期、提醒、优先级、进度、打卡、统计或催促机制。

### 1.2 构思集入口与基础操作

构思集同时提供一级页面与卡片预览中的快速归入入口，以分别服务“带着明确目标继续构思”和“预览时发现关联”两种意图：

```text
发现式路径：卡片预览 → 点按底部构思集按钮选择目标
          或按住底部按钮向上拖动 → 命中已有组或“新建” → 归入构思集

目标式路径：底部“构思集”一级入口 → 构思集总页面
          → 进入已有构思集或点按“新建”进入临时构思集
```

- 构思集总页面是继续、新建和管理构思中内容的稳定一级入口；不得要求用户先进入卡片预览才能继续构思。
- 构思集总页面始终保留“新建”入口。当前有 0 至 5 个构思中构思集时，进入方式保持一致；不得在只有 1 个组时绕过总页面直接进入该组。
- 卡片预览中的快速归入面板从底部构思集按钮附近向上展开；点击面板外或向下滑动可关闭，不使用屏幕中央的大弹框。
- 选择面板的最大展开形态为 **3 列 × 2 行**，最多同时容纳 5 个已有构思集和 1 个“新建”目标；不得改成 6 行纵向长列表。
- 已有构思集依次占用前 5 个单元，“新建”固定在第 2 行第 3 列。构思集不足 5 个时，未占用单元不显示内容、不可命中，但“新建”位置不移动，保证不同数量下操作位置稳定。
- 每个目标单元至少显示可辨识的构思集名称和当前灵感数量；名称过长时截断，不得通过压缩点击区域或缩小到难以阅读的字号容纳全文。
- 卡片预览既支持点按目标归入，也支持按住底部构思集按钮向上拖动并在目标内松手归入。
- 拖动过程中底部构思集按钮保持在原位，不跟随手指移动；手指进入有效目标时仅使用克制高亮，离开后立即取消高亮和命中状态。
- 只有手指最终在有效目标内松开才执行归入；在目标间隙、面板外、已满构思集或不可用“新建”上松手均不改变数据。
- 已有 5 个构思中构思集时，“新建”仍保持原位置但不可用，并说明“当前版本最多支持 5 个构思集”。已有 10 条灵感的构思集显示“10/10”并保持可见，但不可接收新灵感。
- 普通卡片点按仍进入专注编辑。
- 卡片上下切换等核心对象手势不因构思集改变；一级页面始终可通过底部导航切换，并按第 5 节增加带对象优先规则的横滑切换。
- 独立卡片左滑越过阈值后执行“收起”：持续退出卡片流，直到用户主动放回；该操作不删除灵感，也不生成构思小票。
- 已收起灵感仍在全部灵感中显示，用户可“放回卡片流”或直接“归入构思集”。
- 组内仍保留每张卡片的独立文字、附件、时间和编辑能力。
- 普通卡片归入构思集后，不再作为独立卡片重复出现在卡片流；卡片流以一个构思集卡片代表该组，组内详情由构思集工作台承接。
- 构思集左滑越过阈值后先弹出“结束本轮构思”确认框，不立即修改状态或生成小票。
- 用户确认后，当前构思轮次及成员关系一次性形成“已结束”快照，并生成一张构思小票；取消则恢复滑动前位置和状态。
- 若某张卡片不应随本轮收录，用户须在结束前先将它移出构思集。
- 已结束构思集可从“构思历程”的已结束构思集视图找到；“继续构思”会开启新一轮并将构思集及其成员重新放回卡片流，旧小票保持不变。

不改用“长按卡片后向下拖入底部按钮”的方案，以免与卡片上下切换、左滑收起等既有手势发生竞争。

### 1.3 有限边界

| 规则 | V0.2 已确认要求 |
| --- | --- |
| 同时存在的构思中构思集 | 最多 5 个 |
| 单个构思集容量 | 最多 10 条灵感 |
| 单张卡片归属 | 同一时间只能属于 1 个构思集 |
| 超出容量后的行为 | 不自动新建、扩容或复制卡片；第 11 条归入或新增操作不写入，并提示“当前版本每个构思集最多支持 10 条灵感” |
| 组的作用 | 一条正在构思的思考线，不承担无限分类、嵌套或多重归属 |

这些限制用于保持“正在构思”可被重新进入，而不是禁止用户以自己的方式使用 NOTE1。

V0.2 不增加“每轮只聚焦部分卡片”的二级容量概念。一个构思集中的全部成员都属于当前构思内容；结束本轮构思时，当前组内最多 10 条灵感一起形成轮次快照并进入构思小票。

### 1.4 数量反馈

- 卡片页底部的构思集圆形入口，在存在构思中内容时显示右上角数量角标。
- 该角标表示所有构思中构思集内的卡片总数，不表示提醒、红点、待办数量或完成进度。
- 通过长按并向上拖动展开快速归入目标时，每个构思集目标也显示自身的卡片数。
- 数量反馈使用克制的深蓝或同主题色，不使用红色、警告样式、进度环或催促文案。
- 构思集总页面、快速归入托盘中的组目标和构思集工作台入口显示该组内卡片数量，便于用户判断该思考线的容量。

### 1.5 新建与命名

- 快速归入托盘保留“新建”目标。
- 归入“新建”后应立即创建构思集并归入当前灵感，避免拖拽过程中强制输入名称。
- 从构思集总页面点按“新建”后，进入带第一张空白灵感的临时构思集工作台；用户写入内容或修改构思集名称后才正式保存。
- 用户未输入任何内容、未添加附件且未修改名称便退出时，自动丢弃临时构思集，不占用 5 个构思中构思集名额，也不保留空白灵感。
- 用户可以进入构思集后修改名称。
- 自动创建的构思集依次使用“构思集（1）”“构思集（2）”“构思集（3）”等默认名称。编号使用本机持久化的单调递增序号；删除旧构思集后不回收旧编号，避免构思历程与小票出现同名混淆。
- 用户修改名称后不改变编号计数器；后续新建继续使用下一个编号。默认名称不带任务、截止日期或压力含义。

### 1.6 明确不做

- 不允许同一张卡片同时属于多个构思集。
- 不因构思集引入标签、多层分类目录、组嵌套或无限新建组。
- 不因构思集引入项目状态、截止日期、提醒、优先级、完成率、排行榜或效率统计。
- 不自动根据内容建议归入构思集，也不自动将历史内容重新推回用户面前。

### 1.7 验收口径

1. 用户可用现有点按或底部按钮上拖路径，把一张普通卡片加入已有构思集或新建构思集。
2. 第 6 个构思中构思集不可被创建；已有 5 个时，“新建”目标应不可用并说明原因。
3. 已有 10 条灵感的构思集不可再接收灵感；卡片和组数据都不应被部分写入。
4. 同一张卡片加入新组后，不在原构思集中重复存在。
5. 底部总数、快速归入目标数量和工作台入口数量与实际组内卡片数一致；不表现为通知或待办压力。
6. 当前普通卡片的上下切换和左滑收起保持可用；收起不会生成小票，切换一级页面使用底部导航。
7. 卡片归入构思集后，卡片流只显示一个构思集入口，不重复显示 1 至 10 张成员卡片。
8. 全部灵感始终显示全部独立灵感；属于构思集的灵感显示所属构思集名称。
9. 构思集左滑越过阈值后必须先确认；确认才原子结束当前轮次并生成一张小票，取消不改变任何数据。
10. 已结束构思集可从“构思历程”的已结束构思集视图继续构思；新一轮可产生新小票，旧小票不被覆盖。
11. 底部“构思集”一级入口在 0 至 5 个构思中构思集时都先进入构思集总页面；仅有 1 个组时也不得直接跳转。
12. 构思集总页面始终保留“新建”；达到 5 个组后入口仍可见，点按时说明“当前版本最多支持 5 个构思集”，未达到上限时可进入临时工作台。
13. 空白临时构思集退出后不落盘；产生内容、附件或有效名称后正常保存，并在重启 App 后保持。
14. 选择面板最大形态为 3 列 × 2 行，5 个构思集和“新建”均可在普通与较小尺寸 iPhone 上显示；目标名称、数量和可用状态可以辨识。
15. 卡片预览中按住按钮上拖时，按钮本身不随手指移动；只有在有效目标内松手才归入，离开目标后高亮立即取消。
16. 已满构思集显示“10/10”但不可归入；已有 5 个构思集时“新建”不可用。点按与拖拽两种路径使用相同的可用性判断，失败时不产生部分写入。

## 2. 已确认方向：一级导航、灵感时间流与录入

### 2.1 四个稳定一级入口

NOTE1 V0.2 采用接近 X（Twitter）的底部一级导航方式，但只借鉴其“稳定页面入口 + 独立新增按钮”的信息架构，不复制社交信息流、关注关系或其他功能。

底部导航固定为四个带文字标签的一级入口：

```text
灵感｜卡片预览｜构思集｜小票册
```

- **灵感**：默认打开，按时间展示全部独立灵感，也是记录、排序、搜索和管理灵感的首页。
- **卡片预览**：进入纵向卡片流，承担快速重新浏览、收起和归入构思集。
- **构思集**：进入构思集总页面，承担继续构思、新建构思集和进入构思历程。
- **小票册**：进入全部构思小票的成果空间，承担浏览、搜索、选择、分享和再次进入来源构思轮次。
- 四个入口层级平等。卡片预览、构思集和小票册均属于 NOTE1 的核心体验，不再通过首页角落按钮、抽屉或多级跳转隐藏。
- 底部导航始终提供完整、可见的点击路径；不能把一级页面切换只放在隐藏手势中。
- “+”不是第五个标签。它作为独立的浮动录入按钮，位于右下方、底部导航上方，并在四个一级页面保持一致位置。
- 录入面板、键盘、附件选择、完整搜索或批量选择状态出现时，“+”应暂时隐藏或让位，避免遮挡内容与操作；退出这些状态后恢复。
- 所有一级页面为底部导航和浮动“+”预留安全区，列表末项、卡片操作和构思集内容不得被遮挡。

#### 底部导航与通用按钮视觉基线

- 底部导航采用用户本轮确认稿中的悬浮大圆角玻璃容器：浅色半透明材质、细白边界、克制背景模糊与冷色软阴影；不得退化为纯白高亮条、实灰底栏或四个彼此分离的圆形按钮。
- 四个入口均由图标和文字标签构成。选中项使用 NOTE1 深蓝色小圆角方形图标底，图标反白，标签使用深蓝色；未选中项使用低对比蓝灰色线性图标和标签，不增加独立底色。
- 图标语义按确认稿保持稳定：灵感使用带闪光的灵感符号，卡片预览使用叠放卡片，构思集使用文件夹，小票册使用带齿边的小票。实现时优先采用或绘制语义一致的矢量图标，不用含义相近但轮廓明显不一致的临时 SF Symbol 作为最终稿。
- 选中态只改变当前入口，不让整个底栏同步变亮；切换时使用短距离、低幅度的材质和缩放过渡，不使用弹跳、闪白或高亮扩散。
- 顶部选择、搜索、返回等通用圆形按钮使用与确认稿一致的浅色玻璃圆形容器和 NOTE1 深蓝线性图标。默认态保持浅亮而非灰化；按下态仅通过轻微蓝灰染色、细微缩放和一次触觉反馈确认点击，不得变成刺眼纯白。
- “选择”使用圆角方框内勾选符号，不使用裸露文字；图标、容器尺寸、材质亮度和按下态与搜索等同级按钮保持一致。
- 开启“降低透明度”时用不透明浅色底和清晰边界替代玻璃模糊；开启“减弱动态效果”时保留选中状态变化，但取消明显缩放和位移。

### 2.2 “灵感”首页与时间流

- 原独立“安静首页”和“全部灵感抽屉”合并为底部第一个“灵感”页面；UI 标签显示“灵感”，页面内容语义仍是“全部灵感”。
- 页面直接按时间展示全部独立灵感，默认从新到旧；不再只显示最近 5 条，也不再另设左上角“全部灵感”入口。
- 属于构思集、已收起或仍在卡片流中的灵感都继续作为独立记录显示；属于构思集的灵感在摘要下方标明“构思集 · 名称”。
- 顶部采用稳定的操作关系：左侧为统一功能入口，中间显示带明确下拉提示的 `NOTE1⌄`，右侧为搜索图标按钮。左侧入口使用 NOTE1 标识或克制的菜单/个人入口图形，不在尚未登录时伪造用户头像；点按后展开选择、回收站和设置等本机功能。
- 点按 `NOTE1⌄` 只提供与当前页面有关的排序：默认“创建时间从新到旧”，以及“创建时间从旧到新”。不加入来源、标签或未确认的复杂筛选。
- 时间流上方保留一条不显示标题、视觉克制的近期成果摘要。V0.2 默认统计最近 7 个自然日，文案为“本周新增 N 条灵感 · 结束 M 轮构思 · 留下 K 张小票”；数值为 0 的分项可以省略，三项均为 0 时整条摘要隐藏。
- 摘要只使用本机已有数据实时计算，不建立账号、埋点服务器或云端统计；点按摘要不进入任务、排行榜或复杂数据看板。
- 近期摘要不展示使用时长、连续天数、排名、完成率、目标、同比环比或带压力的效率指标；页面主任务仍是快速记录与查看灵感。
- 没有灵感时保持安静空态，并保留浮动“+”入口；不展示任务催促或人为制造的活跃度数据。

#### 已选视觉方向：轻量卡片流

- 灵感时间流采用本轮视觉方案 2：每条独立灵感使用轻量、可变高度的纸张式卡片呈现，保留 NOTE1 的卡片语言，但不得接近卡片预览中的全屏大卡。
- 卡片按时间纵向连续排列，一屏应能自然看到多条灵感或下一张卡片的开头；短内容保持紧凑，长内容只显示 1 至 3 行摘要，点按后进入完整详情。
- 纯文字灵感以正文为主；照片灵感可显示一张横向预览图；语音、PDF 和其他附件使用小型附件摘要，不把首页变成图库或文件管理器。
- 时间是所有卡片的基础信息；“构思集 · 名称”、附件数量等元数据只在相关卡片出现，不在每张卡片重复堆叠。
- 卡片之间依靠留白、轻微材质差异和极克制阴影形成节奏，不使用粗边框、高亮白光或卡片内再套卡片。
- 浮动“+”位于右下方并覆盖在时间流上方，但不得遮挡卡片正文、附件操作或最后一条记录；列表底部需保留相应安全距离。

### 2.3 页面关系与层级

```text
一级：灵感｜卡片预览｜构思集｜小票册

构思集
 ├─ 构思中构思集
 └─ 构思历程
     └─ 已结束构思集与历次构思轮次

小票册
 └─ 全部构思小票
```

- 小票册提升为第四个一级入口，不再要求用户先进入构思集和构思历程。结束本轮构思后仍可直接进入刚生成的小票。
- “构思集”一级页面只展示构思中内容；已结束构思集及其历次轮次通过右上角“构思历程”进入。构思轮次详情可以进入对应小票，小票详情也可以返回来源构思轮次，但两个列表不重复承担彼此的管理职责。
- V0.2 的一级页面切换以底部点击为正式兜底，并支持按固定顺序横滑切换。卡片预览和小票册存在对象横滑时，只有保留边缘区域触发一级页面切换；具体阈值按第 5 节真机调校。
- 页面内部的对象手势继续保留：卡片上下切换、独立灵感左滑收起、构思集左滑结束本轮构思、快速归入拖动和详情页左边缘返回；不得为了一级导航复用同一手势而造成冲突。

### 2.4 搜索、排序与批量选择

#### 搜索

- 点按“灵感”页面右上角搜索后进入完整搜索状态，默认搜索全部本机内容，并提供 `全部 / 灵感 / 构思集 / 小票` 单选筛选项。
- 筛选项明确显示当前对象范围，可随时移除或更换；搜索结果必须标明对象类型，不把灵感、构思集和小票伪装成同一种列表项。
- 在构思集总页面、构思历程或小票册进入搜索时，自动限定并显示当前页面范围，例如“搜索构思集”“搜索小票册”；用户无需再次理解搜索范围。
- 点按结果后，灵感进入灵感详情，构思集进入对应工作台或已结束详情，小票进入小票详情。
- 卡片预览、单个构思集工作台和灵感编辑页不常驻搜索按钮。这些页面以当前对象的阅读与编辑为主，不因“每页都有搜索”而重复放置无效入口。
- 单张小票详情不常驻搜索按钮；详情“更多”中提供“在小票中查找”，只定位当前小票内已经生成的文字，不搜索其他灵感、构思集或小票。
- V0.2 只做本机关键词与对象范围搜索，不加入标签、OCR、语义检索、AI 关联或全库 RAG。

#### 选择

- “灵感”页面不再把选择作为左上角唯一按钮。点按左上角统一功能入口后，可以进入“选择灵感”；选择项使用本轮确认稿中的深蓝圆角方框勾选图标，不增加只包一项的“更多”菜单。
- 小票册需要批量管理时，可以从页面操作入口进入“选择小票”；进入选择状态后的按钮、默认态、按下态和无障碍降级遵循 2.1 的通用按钮视觉基线，不使用裸露的“选择”文字占据顶部主位置。
- 当前 V0.2 已把原“安静首页”和“全部灵感”合并为底部“灵感”一级页面，因此该页面按“全部灵感管理列表”处理，支持批量选择，不再保留一个只显示最近灵感且不支持管理的独立首页。
- “灵感”页面的批量操作为：删除、放回卡片流、归入构思集。只有选中对象全部符合操作条件时才允许提交；批量归入时目标构思集必须有足够剩余容量，任一灵感已属于其他构思集或目标容量不足时不得部分写入。
- 小票册的批量操作为：导出 PDF、系统分享、删除。批量导出或分享生成多份独立小票文件，不把多张不同构思轮次强制合并为一张小票。
- 进入选择状态后显示取消、已选数量、全选和当前对象允许的批量操作；删除等破坏性操作仍需确认。
- 搜索结果只有在已经筛选为单一对象类型时才可进入批量选择；`全部`混合结果不支持跨类型批量操作。
- 构思集总页面暂不提供批量选择：最多仅 5 个构思中构思集，且批量结束会弱化“结束本轮构思”的确认与小票生成语义。
- 卡片预览、单个构思集主工作台、灵感编辑页和小票详情不提供批量选择。构思集内若未来增加卡片概览，可以再评估批量移出，但不属于 V0.2 当前交付。
- 构思历程中的已结束构思集在 V0.2 不提供批量选择；用户逐个查看、继续构思或删除，避免一次结束、恢复或删除多个思考线。

| 页面 | 搜索 | 批量选择与默认操作 |
| --- | --- | --- |
| 灵感（当前首页与全部灵感） | 支持全局搜索 | 支持：删除、放回卡片流、归入构思集 |
| 构思集总页面 | 支持当前范围搜索 | 不支持；最多 5 个，且批量结束会一次生成多张小票 |
| 构思历程·已结束构思集 | 支持当前范围搜索 | V0.2 不支持，逐个处理 |
| 小票册 | 支持当前范围搜索 | 支持：批量导出 PDF、系统分享、删除 |
| 全局搜索结果 | 支持对象筛选 | 筛选为单一对象类型后，使用对应对象的批量操作 |
| 卡片预览 | 不常驻搜索 | 不支持，逐张浏览与处理 |
| 单个构思集工作台 | 不常驻搜索 | 主工作台不支持；卡片概览批量移出为后续候选 |

| 小票详情 | “更多”中提供“在小票中查找” | 不支持 |

#### 左上角功能入口与回收站

- “灵感”页面左上角设置统一功能入口，承担选择、回收站和设置等低频操作；它不是第五个一级页面，也不得替代底部四个核心入口。
- V0.2 入口内至少包含“选择灵感”“回收站”和“设置”。未来登录、账号或可选 AI 配置可以在后续版本评估接入同一入口，但 V0.2 不显示尚不可用的占位项。
- 回收站只保存被删除的最小可恢复对象：独立灵感和构思小票；不保存构思集、构思轮次或构思关系本身。
- 删除一条属于构思集的灵感时，该灵感进入回收站，构思集保留并减少一条成员；若删除后构思集没有任何灵感，则自动移除空构思集，不生成构思小票。
- 删除构思集时，将组内全部灵感分别移入回收站，删除当前构思集与未结束轮次关系；回收站显示这些独立灵感，不显示一个可恢复的构思集对象。已经生成的历史小票保持不变。
- 从回收站恢复灵感时，将其恢复为独立灵感并放回卡片流，不自动重建已经删除的构思集或原成员关系；用户之后可以重新归入构思集。
- 删除构思小票时，只将该小票移入回收站，不修改来源构思集、构思轮次或原始灵感；恢复后重新回到小票册。
- 普通删除后提供约 2 秒的短时撤回，同时始终保留从回收站恢复的路径；短时撤回消失不代表内容已经永久删除。
- 灵感和构思小票从进入回收站的时间起保留 30 天；超过 30×24 小时后自动永久删除。自动清理可以在 App 启动、进入前台或打开回收站时执行，但同一对象只能清理一次。
- 回收站“灵感”区域顶部固定说明：“在回收站中超过 30 天的灵感将会自动删除。”小票区域使用对应说明：“在回收站中超过 30 天的构思小票将会自动删除。”
- 每个对象显示预计永久删除日期或剩余天数；恢复后清除删除时间，再次删除时重新计算 30 天。
- 用户可以在 30 天内单个或批量恢复、永久删除，也可以主动清空回收站。永久删除和清空回收站均需二次确认，并说明附件也可能被永久清理。
- 自动永久删除不再弹出逐条确认，但必须经过统一清理事务；只有没有任何灵感、小票或其他回收站对象继续引用时，底层附件才允许被删除。

#### 设置

- “设置”使用独立页面承载 V0.2 已经真实可用的本机能力，不显示账号、云同步、AI、通知、主题等尚未实现的占位项。
- 设置页首版固定包含“本机备份与恢复”“本机隐私说明”“联系我”和“关于 NOTE1”。
- “本机备份与恢复”复用并升级 V0.1 已有的本机备份能力，备份范围必须覆盖灵感、构思集、构思轮次、构思小票、回收站对象以及仍被引用的附件；恢复前说明会影响当前本机数据并进行二次确认。
- “本机隐私说明”明确说明：内容默认只保存在本机 App 沙盒；V0.2 没有登录、后端、云同步、AI 分析或静默上传。调用系统分享、导出 PDF 或用户主动选择外部文件时，只处理用户明确发起的对象。
- “联系我”显示邮箱 `y2694390075@gmail.com`。点按后优先唤起系统邮件入口并预填收件人；设备无法发送邮件时提供复制邮箱地址的操作和中文反馈，不得点按后无响应。
- “关于 NOTE1”显示应用名称、当前版本号和构建号，并提供只读的产品定位与开源许可入口；不存在对应页面或许可文件时，不显示不可用入口。

### 2.5 文字录入

- 点按浮动“+”后，以克制的原生底部录入面板进入输入状态并自动聚焦键盘；不把整个灵感时间流改造成编辑器。
- 录入框支持多行自适应，正常展示 1 至 5 行；超过可见行数后在输入框内部滚动，不得把操作按钮挤出屏幕。
- 附件、语音、收起键盘和发送操作位于稳定的底部操作区。
- 用户可通过面板内按钮或键盘工具栏明确收起键盘。
- 有未保存文字、语音灵感录音或附件时关闭录入面板，必须确认是否放弃；空白面板可以直接关闭。
- 保存成功后清空本次草稿、关闭录入面板，并将新灵感按当前排序规则加入时间流，同时提供克制的成功反馈。

### 2.6 双语音模式：语音灵感与音频附件

V0.2 明确区分两种声音来源。两者都只保存在本机、都可以播放，但入口和产品语义不同：

| 模式 | 入口与用途 | 保存结果 | 转写规则 |
| --- | --- | --- | --- |
| 语音灵感 | 用户在底部录入面板点按语音入口，直接说出此刻灵感；与文字录入处于同一级 | 保存为普通灵感，并保留本次原始录音；卡片、详情和编辑页均可播放 | 继续支持简体中文本机实时转写，转写文字可编辑；原始录音不会被转写结果替代 |
| 音频附件 | 用户从附件入口加入已有音频，用于保存会议录音、音乐等声音资料 | 作为当前灵感的音频附件保存；卡片摘要、详情和附件预览均可播放 | V0.2 不自动转写，也不把音频内容自动写入正文 |

- 语音灵感入口与文字、照片和文件附件处于同一录入面板，不单独创建录音管理页面。
- 语音灵感首次使用时请求麦克风权限；需要本机转写时再请求系统语音识别权限。麦克风未授权时不能开始录音，并以中文说明；语音识别未授权或设备不支持时，仍允许录制、保存和播放原始音频，只是不生成转写文字。
- 语音灵感的本机转写仅支持当前确认的简体中文。只有设备明确支持本机识别时才启动，不得静默降级为联网识别。
- 转写中的文字实时显示在输入框，并追加到用户原有手动文字之后，不覆盖原文。用户停止录音后可以继续修改文字，再与原始录音一起保存为一条灵感。
- 用户取消尚未保存的本次语音时，删除对应临时录音并撤销本次新增转写，不清空录入面板中原有文字和其他附件；系统中断时保留已经成功落盘的录音与有效转写，并明确提示当前结果。
- 语音灵感即使没有产生转写文字，也可以作为一条只含可播放录音的普通灵感保存；列表与卡片使用“语音灵感”、时长和录制时间形成可辨认摘要。
- 音频附件沿用附件选择与导入流程，保存原文件名、文件类型、大小和可读取的时长；导入失败、格式不受系统播放器支持或空间不足时，不创建残缺附件。
- 两种声音都使用统一、可访问的播放控件，至少支持播放/暂停、当前进度、总时长和 VoiceOver 状态播报；V0.2 不把后台连续播放、播放列表或音乐播放器能力列为交付要求。
- 语音激活和播放状态只使用轻量颜色、文字和触觉反馈，不使用强闪烁、持续跳动或带压力的倒计时。
- 原始录音、音频附件与本机转写内容均不得上传；分享或导出只在用户主动选择相应对象时调用系统能力。

## 3. 已确认方向：构思集工作台与结束本轮构思

### 3.1 小型思考工作台

构思集详情采用“小型思考工作台”方向，不再只是只能按时间向下阅读的普通列表。

- 工作台围绕一条正在构思的思考线展开，不是任务仪表盘。
- 用户可在最多 10 张卡片之间快速切换、反复阅读并继续编辑。
- 组内顺序由用户调整并持久保存；该顺序同时决定结束本轮构思后小票中的内容顺序。
- 当前正在阅读的卡片处于主要视觉层级；前后卡片只露出窄幅圆角纸边，既提示可继续切换，又不挤压正文阅读空间。
- 用户可新增普通组内卡片、移出卡片或修改构思集名称；所有卡片继续拥有独立文字、照片、文件附件和时间信息。
- 不增加特殊“总结卡”类型、隐藏的额外卡片、自动引用图谱或 AI 改写；用户主动新增的总结仍占用正常的 10 条容量。
- 工作台不显示进度、截止日期、完成率、今日任务、连续天数或效率评价。

### 3.2 统一卡片滚动与原位编辑

卡片预览与构思集工作台复用同一套纵向卡片滚动容器和视觉语言，但分别服务“快速阅读”和“集中构思”，不得把两种模式的状态与手势混为一体。

#### 共同视觉与动效

- 当前卡片始终位于主视觉层；前一张和后一张只露出一小部分圆角纸边，不展示可阅读正文或额外操作。
- 第一张卡片只露出后一张纸边，最后一张卡片只露出前一张纸边，不制造不存在的循环内容。
- 上下切换时，目标纸边自然展开并替换当前卡片，形成克制的抽卡、叠卡过渡；不得生硬跳转或出现高亮闪白。
- 两种模式统一使用卡片宽度、圆角、边距、阴影、动画时长和触觉反馈；阴影与材质亮度保持克制。
- 开启“减弱动态效果”时改为短距离位移或淡入淡出，信息层级和操作结果保持不变。
- VoiceOver 只将当前卡片作为主要可访问内容，露出的纸边不作为独立卡片朗读；同时提供等价的上一张、下一张操作。

#### 卡片预览模式

- 用户上下滑动切换卡片，点按当前普通卡片仍进入专注编辑。
- 不常驻显示总卡片数、完成率或进度，避免把回看变成清单压力。
- 普通灵感左滑执行“收起”；切换到“灵感”或“构思集”一级页面使用底部导航。V0.2 不把左边缘右滑设为卡片预览返回首页的必做路径，以免与横向状态操作和 iOS 系统手势形成新的竞争。

#### 构思集模式

- 进入构思集即进入集中构思，不再增加单独的“专注编辑”页面或第二次进入动作。
- 点按当前卡片正文后直接原位编辑；修改自动保存，切换卡片前先保存当前内容，不弹出重复保存提示。
- 进入工作台时不强制弹出键盘；用户主动点按正文后才进入编辑状态。
- 键盘显示时，上下手势优先滚动当前卡片正文并暂停卡片切换；键盘收起后恢复上下切换卡片。
- 键盘工具栏可提供“上一张 / 下一张”作为编辑状态下的等价切换入口，切换前自动保存。
- 仅显示轻量位置提示，如“4 / 10”；不得使用常驻编号条。位置提示可以作为打开全部卡片概览与排序的入口。
- 构思集成员卡片左滑不执行“收起”，也不单独结束本轮构思；结束动作只作用于卡片流中的构思集卡片。

### 3.3 结束本轮构思

- 用户在卡片流中左滑构思集，越过阈值后弹出确认框；弹框前不改变构思集、成员或小票数据。
- 确认框标题为“结束本轮构思？”，说明为：

  > 确认后将结束本轮构思，并自动推荐“经典票”或“胶卷票”，生成一张构思小票。

- 主操作为“结束并生成小票”，次操作为“取消”。
- 用户确认后，“结束本轮构思”一次性处理当前构思轮次及其全部成员关系，不允许只成功一部分。
- 结束后当前构思轮次状态变为“已结束”，构思集及其成员退出当前卡片流；构思集作为思考线仍可从“构思历程”的已结束构思集视图继续构思。
- 系统在同一次原子操作中生成构思小票并保存到小票册，不要求用户再执行一次“保存小票”。
- 取消后构思集恢复滑动前位置，保持“构思中”，不生成小票。
- 完成反馈使用一次明确但克制的收束动画和触觉反馈，文案为：

  > 本轮构思已结束，N 条灵感已收录。

- 提供短时撤回。撤回必须同时恢复构思集、成员关系和状态，并撤销本次刚生成的小票，不能留下半完成数据。
- 在短时撤回窗口结束前，本次结束与小票生成视为同一个可撤销事务；窗口结束后，小票成为该轮固定存根。

#### 小票生成动效

- 用户确认“结束并生成小票”后，先完成数据快照与本机保存，再播放小票生成动效；动画不得成为数据落盘的前置条件，也不得因中断而生成重复小票。
- 出票结构直接参考 Uiverse 的 MIT 授权 [`Print Receipt Card`](https://uiverse.io/dexter-st/friendly-cow-59)：以一个克制的出纸口或票据夹为源点，小票纸张沿纵向连续送出，内容随纸张推进自上而下显现，最终形成完整构思小票。
- 结果出现与停止收束参考 Dribbble [`New Payment Receipt`](https://dribbble.com/shots/15488388-New-Payment-Receipt) 的短促确认感；只借鉴纸张落位、状态确认与视觉收束，不复制支付业务、涟漪验真或商业收据内容。
- 原生实现复刻其“出纸—内容显现—停止收束”的核心节奏和空间关系，不照搬网页 DOM、CSS 尺寸或商业收据文案；纸张材质、深蓝文字、圆角、阴影和背景仍使用 NOTE1 设计变量。
- 出纸过程中不得同时弹出第二张结果卡或重复展示结束文案。纸张停止后只保留一张可继续阅读的小票，并显示“本轮构思已结束，N 条灵感已收录”。
- 生成阶段结束时提供一次明确触觉反馈；不得在每段内容出现时连续震动。动画未完成前可以等待，但不得用不可跳过的长动画阻止返回；具体时长在动效原型和真机筛选后确定。
- 开启“减弱动态效果”时，不执行长距离出纸，改用短距离展开与淡入；小票仍须已经保存并可以进入小票册。

### 3.4 状态语义

- 构思轮次的用户可见状态为“构思中 / 已结束”；构思集是承载一轮或多轮思考的逻辑容器，“已结束”不表示整条思考线永久完成。
- 普通灵感使用“卡片流中 / 已收起”的预览状态，不使用“完成 / 未完成”或“已归拢 / 未归拢”。
- 普通灵感可以长期保持为独立灵感，不必为了获得合法状态而归入构思集。

### 3.5 一轮一票与继续构思

- 每次结束本轮构思只生成一张小票；小票保存的是当前构思轮次结束时的内容、顺序和过程快照。
- 已生成小票的内容快照不可被后续编辑悄悄改写。
- 用户希望继续思考时，从构思历程中的已结束构思集或其构思小票发起“继续构思”。该操作在原构思集下开启新一轮，不复制出一个同名构思集。
- 新一轮默认带回上一轮结束时的全部成员灵感及其顺序，构思集重新进入卡片流，并占用 5 个构思中构思集名额中的 1 个。
- 若当前已经存在 5 个构思中构思集，“继续构思”仍保持可见，但不可直接执行；系统说明“当前版本最多支持 5 个构思集”，不自动结束、替换或删除现有构思集。
- 进入新一轮后，用户可以继续编辑和排序原灵感，也可以移出成员或加入新灵感；任意时刻仍不得超过 10 条，单张灵感仍只能属于 1 个构思集。
- 新一轮对灵感正文、附件和顺序的修改只影响当前灵感及之后的构思状态；上一轮构思小票继续显示结束当时的固定快照。
- 新一轮再次执行“结束本轮构思”后生成一张新小票。新旧小票按照构思轮次归属于同一个构思集，并按轮次时间排列。
- 多轮小票之间应保留来源关系，使用户能看见同一条思考线经历的轮次，而不是覆盖旧结果。
- **待技术设计**：底层采用原灵感加轮次关系，还是为成员关系建立修订记录；无论采用哪种实现，用户可见行为必须符合上述规则，且旧小票快照保持不变。

### 3.6 验收口径

1. 卡片预览与构思集工作台使用一致的纵向卡片尺寸、露边、切换动画和触觉反馈，并分别保持各自的手势规则。
2. 第一张、最后一张和只有一张卡片时不显示错误方向的纸边；露出的纸边不泄露正文，也不形成额外 VoiceOver 焦点。
3. 用户可在构思集内快速切换最多 10 张卡片，原位编辑、调整顺序、移出或新增普通卡片。
4. 用户调整的内容和顺序在切换卡片、退出工作台和 App 重启后保持，并用于生成小票。
5. 键盘显示时正文可以正常滚动且不会误切卡；键盘收起后恢复卡片切换。
6. 构思集左滑越过阈值后只弹确认框；取消不改变状态，确认后当前轮次及全部成员关系一次性形成“已结束”快照。
7. 确认结束后自动生成且只生成一张小票；短时撤回不会遗留孤立小票或错误状态。
8. 已结束构思轮次可在“构思历程”的已结束构思集视图中查看并继续构思。
9. 普通灵感左滑只执行“收起”，不触发构思小票。
10. “继续构思”在原构思集下创建新轮次，默认恢复上一轮的全部成员及顺序，不创建重复构思集。
11. 继续构思后占用 1 个构思中构思集名额；已有 5 个构思中构思集时操作被阻止并说明原因，不改变任何现有状态。
12. 新一轮可以编辑、排序、移出或加入灵感，仍遵守单组最多 10 条和单卡单组规则。
13. 新一轮修改后，旧小票的文字、附件、顺序和过程数据保持结束时快照，不随当前灵感变化。
14. 同一构思集再次结束后新增且只新增一张小票；构思历程能够按轮次查看同一构思集的多张小票。
15. 小票生成动效遵循“出纸—内容显现—停止收束”顺序，动画开始前数据已经可靠保存；系统中断、退出或减弱动态效果均不会产生重复或丢失的小票。

## 4. 已确认方向：小票册与构思小票

### 4.1 产品目的

普通的卡片展开或文本整理稿不足以表现一轮思考如何形成，也不能给用户清晰的结束仪式。

构思小票把本轮的时间路线、有效编辑、卡片内容和附件收束为一个可收藏、可带走的成果；小票册用于保存全部构思小票。

小票取代“整理稿”的展示形态，但不取消内容带走能力：同一份小票应支持在 App 中阅读、导出 PDF、系统分享和复制为干净文本。

初步用户调研显示，部分 NOTE1 潜在用户为艺术、设计和摄影类学生或创作者，其灵感可能主要由照片、绘画和视觉参考构成。因此，小票不能只服务纯文字，也不得为了传统窄纸小票的外观牺牲图片质量。

### 4.2 小票册入口与信息结构

- 构思集总页面只展示当前“构思中”的构思集；已结束内容不与正在构思的内容混排。
- 构思集总页面右上角设置“构思历程”入口。构思历程用于查看已结束构思集、历次轮次及其来源关系，不再作为小票册的必经入口。
- 已结束构思集视图按最近结束时间展示构思集，可查看组内卡片与历史轮次，并执行“继续构思”；当前已有 5 个构思中构思集时，入口保持可见但不可执行，并说明容量原因。
- 小票册作为第四个底部一级页面，按构思轮次结束时间组织全部小票，每一轮只保存一张构思小票；小票不与独立灵感或构思集混入同一列表。
- 小票册根页面采用已确认的“票据夹抽取”方案，不使用 iOS 文件式三列网格、小红书式双列瀑布流、月份缩略图墙或普通纵向列表。根页面一次聚焦一张当前小票，以票据夹和后方纸张露边表达收藏与累积。
- 当前小票显示足以辨认内容的固定高度预览，包括构思集名称、结束时间、灵感数量、少量正文和必要的照片摘要；超长小票不得在根页面缩成无法阅读的完整长图，也不得为了展示全文无限拉长根页面。
- 前后小票仅显示克制的纸张侧边或底边，不展示可误读的完整正文，不形成独立 VoiceOver 焦点。用户左右滑动切换当前小票，首尾不循环。
- 用户在当前小票上向下拖动执行“抽取”。拖动过程由同一进度同步控制纸张位移、票据夹松开、阴影和后方小票层级；越过阈值后进入完整小票详情，未越过阈值自然回弹。
- 点按当前小票或明确的“抽取查看”入口与下拉抽取等价，保证隐藏手势不是唯一入口。
- 构思历程中的具体轮次可以进入对应构思小票；小票详情也可以查看来源构思集和轮次。两者共享同一份小票数据，不生成重复副本。
- 全部灵感只展示独立灵感，包括卡片流中、已收起、构思中和属于已结束构思集的灵感。
- 属于构思集的灵感仍作为独立记录显示，并在灵感下方标明“构思集 · 名称”；归入构思集不会使它从全部灵感消失。
- 结束本轮构思后的结果反馈可以直接进入本次新生成的小票，不要求用户先进入小票册列表。
- 搜索与批量选择遵循 2.4：根级搜索可按灵感、构思集和小票切换对象范围；小票册内部搜索自动限定为小票；小票册可批量选择，单张小票详情不常驻搜索或选择。
- 小票详情优先显示本轮成果；用户仍可进入小票快照中的原始卡片和附件。

### 4.3 小票内容

每张构思小票至少包含：

- NOTE1 标识和小票唯一编号；
- 构思集名称；
- 本轮开始时间、结束时间和持续时间；
- 卡片数量、有效编辑次数、附件数量和最终文字数量；
- 卡片进入、编辑和结束形成的克制时间路线；
- 按工作台顺序排列的卡片文字；
- 卡片中的照片、文件附件名称及其归属关系；
- “本轮构思已结束，N 条灵感已收录”的结束信息。

“有效编辑次数”定义为：用户进入一次编辑状态，内容实际发生变化并结束本次编辑，记为一次；不得按每次键盘输入、自动保存或光标变化累计。

小票不显示完成率、效率评分、连续打卡、排名、与其他用户比较或任何催促性指标。

### 4.4 生成与收藏

1. 用户左滑构思集越过阈值，系统弹出“结束本轮构思？”确认框。
2. 用户取消时恢复原位，不结束构思、不生成小票。
3. 用户选择“结束并生成小票”后，系统完成当前轮次与成员关系的原子状态变更。
4. 系统根据内容推荐“经典票”或“胶卷票”，立即生成小票并保存到小票册。
5. 小票按 3.3 的 `Print Receipt Card` 参考执行“出纸—内容显现—停止收束”动效，并在收束时提供一次明确触觉反馈。
6. 用户可直接返回，也可切换模板、导出 PDF、系统分享或复制文字。

即使用户不切换模板、不导出也不执行额外操作，小票也必须已经可靠保存。

小票的内容与过程快照固定；模板属于表现层，用户之后仍可在“经典票 / 胶卷票”之间切换，且不改变原始内容。

### 4.5 两个基础模板

V0.2 只提供两个通用模板，不提供自由拖拽、字体上传、贴纸、素材市场或深度 DIY。

#### 经典票

- 适合数字、文字和过程信息为主的构思集。
- 强调组名、时间、编辑信息、文字路线和按顺序排列的正文。
- 少量照片以封面或克制缩略图呈现；非图片附件显示文件名和类型。
- 使用与 NOTE1 一致的浅色纸张、深蓝文字和清楚的阅读层级。

#### 胶卷票

- 适合照片、绘画、扫描件和视觉参考较多的构思集。
- 照片以纵向胶片或连续画面方式排列，尽量保留原始比例，不强制裁成统一正方形。
- 每张照片保留所属卡片的时间和文字说明；同一卡片多张照片连续呈现。
- 胶卷票可保持彩色，不因未来可能支持热敏打印而提前降级为黑白。

### 4.6 模板推荐与切换

模板推荐采用本机确定性规则，不依赖 AI：

- 照片少于 3 张，且大部分卡片以文字为主：推荐经典票。
- 照片达到 3 张，或超过一半卡片包含照片：推荐胶卷票。
- 图文数量接近时，可参考用户上一次选择。
- 推荐仅决定默认展示，用户可一键切换另一模板。

模板切换只改变整张小票的统一风格，不提供单个元素的深度编辑。

### 4.7 App、PDF 与内容带走

- App 小票与 PDF 使用同一份内容数据和排版规则，保持字体、颜色、图片顺序和整体风格一致。
- V0.2 初始 PDF 默认使用 A4 纵向页面，构思小票作为居中的窄幅内容列排版；该默认值优先保证系统预览、保存、普通打印和跨应用分享的兼容性，不预设热敏纸尺寸。
- App 中以纵向滚动阅读；PDF 根据 A4 可用高度自动分页，不要求与屏幕像素完全一致。分页应优先在卡片、时间路线或附件块之间发生，避免拆开一张照片及其说明；单个内容块超过一页时才允许内部拆分。
- 超长图片保持宽高比并缩放到内容列宽度；不得为了塞入单页而压缩成不可辨认缩略图。单张图片过高时允许独占一页或跨页裁切，但不得丢失原图，用户仍可从小票附件入口打开原始文件。
- App 可使用本机缩略图保证浏览流畅；PDF 导出必须使用可用的高分辨率图片，避免把屏幕缩略图放大。
- 首版 PDF 以可正确导出、分页、分享和打印为验收目标；视觉边距、分页细节和图片压缩参数在小票功能完成后通过真实导出样本继续调整，不阻塞数据层与小票闭环开发。
- PDF 通过系统分享保存或交给普通打印流程；V0.2 不直接连接任何热敏机或厂商打印 SDK。
- 用户可复制不带小票装饰的纯文本或 Markdown，内容按构思集顺序排列，便于交给备忘录、Obsidian、Codex 或其他工具继续开发。
- V0.2 不提供 NOTE1 公网分享链接，不为此建立服务器或云端存储。

### 4.8 小票册视觉原则

- 小票册使用“票据夹 + 当前小票 + 前后纸张露边”的单焦点构图。票据夹是收藏隐喻和抽取动效的固定空间锚点，不表现为真实尖锐金属钉，也不做成占据大面积的写实机械装置。
- 左右换票以 Vimeo [`Ticket Stub Cards Microinteraction`](https://vimeo.com/1061847322) 和 YouTube [`SwiftUI Stacked Carousel`](https://www.youtube.com/watch?v=af889OfDg-g) 为联合参考：当前小票跟手移动，目标小票从后方纸张层级进入主视觉；松手后使用连续、低回弹的吸附动画停在中心，不突然跳页、不闪白，不做 Tinder 式甩飞、首尾循环或过度 3D 翻转。
- 下拉抽取参考 Reddit [`Smooth SwiftUI stacked card interaction with a rubber like feel`](https://www.reddit.com/r/iosdev/comments/1t5ffnm/smooth_swiftui_stacked_card_interaction_with_a/) 的对象关系：当前小票被拉出时，后方堆叠同步响应并补位。NOTE1 只保留克制的夹口松开、纸张层级和补位反馈，不使用夸张橡胶抖动；进入详情后才展示完整长票和内部纵向滚动。根页面的固定预览高度与详情页的真实内容长度相互独立。
- 上述参考组合用于确定对象关系与动效意图，不代表逐帧照搬。实际位移、阈值、阻尼、持续时间、景深、触觉和减弱动态效果版本必须通过独立原型与真机测试确定。
- 经典票与胶卷票可以在同一票据夹中按时间混合浏览，通过纸张内容和照片比例体现模板差异，不拆成两个平行小票册。
- 小票使用 NOTE1 的深蓝色和浅色基线；图片型小票允许照片成为主要视觉内容。
- 不加入烟花、积分、徽章或夸张庆祝；成就感来自零散灵感已经形成可见存根。
- 建议文案：

  > 每一轮思考，都留下一张存根。

### 4.9 固定快照、附件与删除关系

- 构思小票在当前轮次结束时生成不可变快照。之后编辑、删除或重新归入原灵感，不得改变已经生成的小票；同一构思集继续构思并再次结束时生成新轮次和新小票，不覆盖旧小票。
- 小票正文、卡片顺序、过程事件和附件关系都属于快照。展示模板可以切换，但不能改写快照内容。
- 照片在小票中直接显示适合当前模板的预览，进入详情或导出时使用快照引用的原始质量资源；语音显示可播放附件条、时长和必要状态；PDF 与其他文件显示文件名、类型、大小及可生成时的首页预览，点按后使用系统预览打开，不把整份 PDF 强行展开在窄长小票中。
- 附件底层采用不可变文件资源与引用关系，而不是为每张小票无条件复制一份相同文件。原灵感和每张小票快照分别持有引用；只要任一小票仍引用该附件，用户从原灵感删除附件或删除原灵感后，旧小票中的照片、语音、PDF 与其他文件仍可查看。
- 删除构思小票不影响来源构思集和灵感。小票从回收站永久删除后，才移除该小票对附件资源的引用；只有没有任何灵感、小票或回收站对象继续引用时，底层文件资源才允许被安全清理。
- 删除构思集时不生成新的小票；组内灵感分别进入回收站，已经存在的旧小票及其附件快照继续保持固定。

### 4.10 验收口径

1. 确认结束当前构思轮次后自动生成一张且只生成一张小票，并在重启 App 后仍可从小票册读取；取消不生成。
2. 小票册顶层按构思轮次显示整体小票，不展开为 1 至 10 条重复记录。
3. 经典票可完整承载纯文字和少量附件；胶卷票可承载多张照片并保留可辨识画面。
4. 本机推荐规则结果稳定；用户一键切换模板后内容、顺序和历史数据不变。
5. App 和 PDF 的内容、样式与图片顺序一致；长内容和多图可以分页，不丢失正文或附件关系。
6. 小票可通过系统分享导出 PDF，也可复制纯文本或 Markdown。
7. 全部灵感可直接找到构思集内的独立灵感并看到所属构思集；底部“小票册”一级页面只展示构思小票，并可进入来源构思轮次。
8. 小票不出现完成率、效率、连续天数、排行榜或催促性表达。
9. 小票册根页面使用票据夹单焦点预览；左右滑动能够切换小票，首尾不循环，正常水平切换不会误触下拉抽取。
10. 当前小票下拉越过阈值后进入完整小票详情，未越过阈值回弹；点按或“抽取查看”提供等价路径。
11. 文字型长票和多照片胶卷票在根页面均保持可辨认摘要，完整内容只在详情展开；不得退化为不可读长图缩略图。
12. 生成小票后修改或删除原灵感、照片、语音、PDF 或其他附件，旧小票的文字、顺序与附件仍保持可读；同一构思集的新轮次不会覆盖旧小票。
13. PDF 和其他非图片附件在小票中使用清楚的文件摘要与系统预览入口，不因无法在窄票中完整展开而丢失文件或阻断小票生成。
14. 默认 A4 PDF 可以被系统预览、保存和分享；分页不截断普通照片说明或遗漏卡片，超长图片仍可访问原始附件。

## 5. 已确认方向：全面屏手势体系

### 5.1 设计原则

- NOTE1 优先适配全面屏 iPhone 的边缘手势和直接操控，但任何核心能力都不得只依赖隐藏手势；按钮、菜单或辅助功能操作必须提供等价路径。
- 手势服务于“更快进入、自然翻阅、低摩擦返回”，不为展示动效而增加复杂手势、连续手势组合或需要学习的手势密码。
- 页面切换、卡片操作、正文滚动和文本编辑必须先锁定方向和操作对象；一次手势开始后不得在中途从纵向滚动突然变成横向完成。
- 删除、收起、结束等会改变状态的手势必须具备明确阈值、可取消的跟手反馈，以及确认或短时撤回；轻微误触不得改变数据。
- 全部手势使用一致的空间方向、材质响应和克制触觉；开启“减弱动态效果”后减少位移，不改变结果和可操作性。

| 构思历程 | 从左边缘向右滑 | 返回构思集总页面 | 左上角返回按钮；不影响底部四个一级入口 |
| 已结束构思集或轮次详情 | 从左边缘向右滑 | 返回构思历程 | 左上角返回按钮；不使用横滑直接改变构思状态 |
| 小票册根页面 | 左右滑动当前小票 | 切换上一张或下一张构思小票 | 当前小票居中，前后仅露纸边；首尾不循环；搜索或选择状态下暂停 |
| 小票册根页面 | 向下拖动当前小票 | 跟手从票据夹中抽取，越过阈值后进入小票详情 | 点按当前小票或“抽取查看”；未越过阈值回弹 |
| 小票详情 | 从左边缘向右滑 | 返回底部“小票册”一级页面 | 左上角返回按钮；小票册根页面本身不设置“返回上一层” |

### 5.3 手势优先级与防误触

1. 一级页面横滑采用对象优先规则：灵感时间流和构思集总页面未命中可交互控件时，可以整页横滑切换；卡片预览和小票册已有高频横向对象手势，只允许从页面保留的左右边缘区域切换一级页面。
2. 卡片预览中的非边缘左滑继续执行灵感收起或请求结束构思，不得同时切换到“构思集”；小票册当前小票上的非边缘左右滑继续切换小票，不得同时切换一级页面。
3. 手势从系统或页面保留的左、右边缘区域开始时，优先判定页面导航；不得同时触发卡片收起、结束构思、换票或文本选择。若当前页面位于导航栈详情层，系统式返回优先于一级页面切换。
4. 非边缘手势先比较横向与纵向意图，方向明确后锁定到本次手势结束；未形成明确方向时不执行状态操作。
5. 文本编辑、附件预览、列表和正文可滚动区域优先处理自身滚动；键盘、搜索或批量选择状态显示时暂停一级页面横滑。
6. 卡片横向状态操作只在卡片主体的有效区域开始；按钮、附件、链接和可编辑正文上的触摸不直接触发收起或结束。
7. 未越过提交阈值时，页面或卡片必须随手势平滑回到原位，不出现“已收起”“已结束”等成功反馈。
8. 越过提交阈值时只提供一次轻触觉提示；继续拖动不得反复震动或加深高亮。
9. 多个页面不得为同一方向定义互相矛盾的高频操作；新增手势前必须检查本表并说明优先级。

具体边缘宽度、位移、速度和角度阈值由交互与技术设计在真机上调校，不在 PRD 中写死像素值；验收以“正常纵向滚动不误触横向操作、轻微横移不改变状态”为准。

### 5.4 动效、无障碍与降级

- 页面切换和卡片移动应跟随手指进度，取消时自然回弹，提交后沿当前方向完成，不在松手后突然跳转。
- 收起和结束本轮构思的颜色反馈在接近提交阈值后才逐渐出现，轻微横移时保持接近初始材质，避免过早显示强烈完成暗示。
- VoiceOver 下为全部手势提供命名清楚的按钮或自定义操作，并播报操作对象和结果；露出的前后卡片纸边不获得独立焦点。
- “减弱动态效果”开启时使用短距离位移或淡入淡出；“降低透明度”开启时保证按钮边界、文字和状态仍清晰。
- 任何手势识别失败、系统中断或动画取消都不得留下半完成状态、重复小票或丢失编辑内容。
- “真机原型参数”指手势提交阈值、方向锁定角度、位移、速度、弹簧阻尼、动画持续时间、景深变化和触觉时机，不只是选择某个 iPhone 机型或 iOS 版本。
- V0.2 复用 V0.1 的主测试设备和模拟器作为日常调校基线；正式验收仍至少覆盖一台实际 iPhone、最低支持的 iOS 17 运行环境、当前主开发运行环境，以及一档较小屏幕或较大辅助字号。不得只用单一高版本大屏模拟器证明手势和布局已经完成。

### 5.5 验收口径

1. 用户可以只通过可见按钮和底部标签完成全部核心闭环，也可以使用已经确认的对象手势加速操作。
2. “灵感 / 卡片预览 / 构思集 / 小票册”四个底部入口切换稳定；列表、卡片、工作台和小票内容不被底部导航或浮动“+”遮挡。
3. 卡片预览的上下切换、非边缘左滑收起或结束、边缘一级页面切换可以共存；任何隐藏手势都不得替代底部导航。
4. 构思集选择面板最大使用 3 列 × 2 行；按钮上拖只有在手指最终命中有效目标时才归入，离开目标后高亮和命中状态立即取消，按钮本身不跟随手指移动。
5. 键盘显示时，工作台卡片切换和可能冲突的全局手势暂停，正文滚动、文本选择和键盘收起保持正常。
6. 未越过阈值的卡片和页面能平滑复位，不生成成功文案、触觉或数据变更。
7. 所有状态改变均可确认或短时撤回，撤回期间不阻断继续上下切换卡片。
8. VoiceOver、减弱动态效果和降低透明度开启后，所有手势能力仍有等价入口且结果一致。
9. 真机快速斜滑、慢速拖动、短距离横移和连续上下翻卡不会误触收起、结束构思或返回。
10. 小票册先锁定水平或向下抽取方向；左右换票不会同时拉出小票，下拉抽取不会改变当前小票索引，斜向短滑不提交任何动作。
11. 四个一级页面可以通过横向手势按固定顺序切换；在卡片预览和小票册中，非边缘对象手势保持原行为，只有保留边缘区域触发一级页面切换，且所有页面仍可通过底部标签到达。

## 6. 已确认补充：声音资源的生命周期

### 6.1 数据关系

- 语音灵感和音频附件不是两个新的顶层内容对象；它们都依附于一条灵感，并通过来源类型区分“用户现场录入”与“用户导入已有音频”。
- 两者共用不可变本机声音资源、元数据和播放器能力。转写文字属于灵感正文的一部分，声音资源仍独立保留，任何一方失败都不得静默覆盖另一方。
- 构思小票生成时固定引用当时已经保存的声音资源。之后用户从原灵感移除声音或删除原灵感，旧小票仍应可以播放；只有没有灵感、小票或回收站对象继续引用时才允许清理底层文件。

### 6.2 删除、恢复与失败

- 用户从灵感中删除语音灵感录音或音频附件时，先解除当前灵感引用；仍被旧小票引用的声音不得从磁盘删除。
- 灵感进入回收站后，其声音引用随灵感一起保留；恢复后继续可播放。灵感永久删除时只移除该灵感持有的引用。
- 录音开始后、灵感保存前使用临时资源；用户取消、录音初始化失败或保存事务回滚时必须清理临时文件，不得留下无法访问的孤立录音。
- 本机转写失败不删除录音，播放失败不删除转写文字；错误反馈要明确当前仍然保留了什么。

### 6.3 V0.2 边界

- V0.2 不提供云端转写、自动会议纪要、语音总结、说话人识别、音频剪辑、播放列表或后台音乐播放。
- 音频编码、单条录音时长、导入文件大小与支持格式属于编码前必须确定的技术与产品参数，记录在待讨论清单；这些参数不得改变“双模式均保存并可播放”的核心语义。

## 7. 后续候选：构思集内 AI 整理

### 7.1 已确认的版本边界

- V0.2 不接入 AI，不因 AI 建立账号、后端、云同步、向量数据库或全库 RAG。
- 第 2.6 节调用 iOS 系统提供的本机语音识别，只用于用户主动发起的语音灵感实时转写，不属于本节所排除的生成式 AI 或联网模型能力；无论是否转写，原始录音都保存在本机。
- 构思小票依靠本机规则收集、排序和格式化，不宣称理解内容或自动总结。
- V0.2 的完整闭环不得依赖用户配置 API Key。

### 7.2 后续候选方案

后续版本可评估用户自带 DeepSeek API Key 的可选能力：

- API Key 由用户自行申请和付费，并保存在 iOS Keychain。
- App 在用户明确触发并确认发送范围后，直接向 DeepSeek API 请求，不经过 NOTE1 自建服务器。
- 输入范围优先限制为当前一张构思小票或当前构思集，不默认分析全部历史记录。
- AI 可生成本轮总结、主要结论、未解决问题和后续推进方向。
- AI 结果作为与小票关联的独立草稿，不写入或覆盖小票的固定内容快照，也不自动合并或改写原始卡片。
- 未配置 API、网络失败或用户拒绝发送时，不影响小票生成、PDF 导出和完整本机闭环。

本节只记录未来产品方向，不作为 V0.2 的设计或开发依据。

## 8. V0.2 当前范围、依赖与开发默认值

### 8.1 已确认进入 V0.2 产品范围

- 原“灵感组”收束为构思集；最多同时存在 5 个构思中构思集，每组最多 10 条灵感，单卡同时只属于一个构思集。
- 独立灵感左滑后“收起”，持续退出卡片流直到用户主动放回，但仍保留在全部灵感，并可放回卡片流或归入构思集。
- 卡片预览与构思集工作台复用统一的纵向卡片滚动容器；当前卡片居中，前后卡片仅露出窄幅纸边，并按模式区分阅读、原位编辑、计数和状态手势。
- 构思集左滑越过阈值后弹出确认框；确认才结束当前轮次并自动生成构思小票，取消不改变数据。

- 浮动“+”位于右下方、底部导航上方，在四个一级页面保持一致；录入、搜索、附件或选择状态下隐藏或让位。

- 构思集内灵感仍在“灵感”时间流中独立显示并标明所属构思集。
- 构思集总页面只展示构思中内容，右上角“构思历程”进入已结束构思集和历次轮次；小票册使用独立底部一级入口，轮次与小票之间保留双向来源关系。
- 已结束构思集可“继续构思”：默认带回上一轮全部成员和顺序，在原构思集下开启新一轮并占用 1 个构思中名额；已有 5 个构思中构思集时阻止操作且不自动替换。新一轮可调整成员并再次生成小票，旧小票快照保持不变。

- 根级搜索支持“全部 / 灵感 / 构思集 / 小票”范围，集合页搜索自动限定对象；灵感支持批量删除、放回卡片流和归入构思集，小票册支持批量导出 PDF、系统分享和删除，已结束构思集不提供批量选择。
