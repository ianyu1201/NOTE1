# NOTE1 V0.2 源码审查与 V0.2.1 稳定化建议

> 状态：工程稳定化参考，不定义 V0.3 产品需求  
> 更新日期：2026-08-08
> 当前审查对象：`codex/note1-current-folder-governance`，代码治理基线 `6aafa9b1198d`
> 历史初审对象：`codex/note1-v02@b7a4e0744861`

## 1. 总体结论

V0.2 已形成可运行的领域模型、持久化基础、页面闭环和自动化测试，但尚未满足正式封版条件。V0.1/V0.2 双实现维护成本已通过 ADR-004 和代码治理关闭；V0.3 大范围 UI 改造前，仍应关闭数据风险、性能风险和真机验收缺口。

稳定化与产品设计可以并行推进，但必须在隔离工作树和固定提交上进行，不能互相覆盖。

## 2. 已确认优点

### 2.1 技术边界符合产品定位

- 原生 SwiftUI iPhone App；
- 最低 iOS 17；
- 数据与附件保存在本机；
- 无登录、无后端、无云同步、无 AI；
- 构思轮次与小票快照具备独立领域表达。

### 2.2 领域和持久化基础可继续演进

现有实现已覆盖灵感、构思集、构思轮次、构思小票、附件、回收站及相关约束。V0.3 不需要为视觉优化重写数据模型。

### 2.3 自动化测试基础较强

2026-08-08 在当前代码治理基线上的独立结果为 69 项测试通过、0 项失败；通用 iOS 构建和静态分析均成功。历史 86/100 项结果包含已退出正式 target 的 V0.1 测试，不能作为当前基线数量。当前结果仍不代表真机体验、无障碍、文件提供器和跨系统材质已经验收；后续代码提交必须重新运行。

## 3. 已确认风险

### 3.1 P1：附件预览存在重复标识风险

#### 现象

附件列表若以文件名、显示名或其他非唯一字段作为 SwiftUI 标识，不同附件可能产生重复 ID，导致预览错位、更新异常或删除错误对象。

#### 处理要求

- 使用持久化附件 ID 作为唯一标识；
- 旧数据缺少 ID 时提供稳定迁移或兼容策略；
- 增加同名附件、多类型同名附件和删除后重新添加的测试；
- 不把未保存的历史运行警告写成当前已复现证据，关闭以代码、测试和运行记录为准。

### 3.2 P1：大备份和恢复可能阻塞主线程

#### 风险

备份、恢复、压缩、校验或复制大量附件若在主线程执行，会造成界面冻结、系统 watchdog 风险及恢复过程中状态不清楚。

#### 处理要求

- 文件扫描、压缩、解压、校验和批量复制移出主线程；
- UI 状态更新回到主线程；
- 提供进度、取消或明确不可取消说明；
- 恢复前验证空间、格式和版本；
- 失败时保留原数据，并给出可理解的错误结果；
- 用含多张照片、PDF 和音频的代表性数据集验证。

### 3.3 已关闭：V0.1 与 V0.2 双实现同时编译

#### 历史风险

旧页面、旧模型或旧入口与 V0.2 新实现同时保留，会导致：

- 修复落在错误实现；
- 两套术语和状态继续漂移；
- 编译体积、依赖和测试边界不清；
- V0.3 UI 改造重复劳动。

#### 关闭结果

1. 已建立 V0.1 能力到 V0.2 实现的非回归映射；
2. 已取得用户授权，旧页面、旧模型、旧入口和只服务旧路径的测试已从正式 target 清除；
3. 当前入口、领域层和持久化统一为 `V02AppShellView`、`V02Store`、`V02DomainEngine`；
4. 69 项 XCTest、通用 iOS 构建和静态分析已通过；
5. 历史实现由 `v0.1.0` 标签和 Git 历史保存，处置依据见 ADR-004。

### 3.4 P2：高频编辑可能反复编码完整状态

#### 风险

若每次文本变化都同步编码并写入完整 JSON，长文本、附件元数据和大量历史记录会造成输入延迟和不必要磁盘写入。

#### 建议

- 检查保存触发频率和编码范围；
- 使用防抖、显式保存节点或增量脏标记；
- 应用进入后台和编辑页退出时确保落盘；
- 用真实长文本和附件数据进行输入延迟、保存耗时和内存测量后再决定重构幅度。

不得仅凭代码形态宣称已存在性能故障。

### 3.5 P1：测试偏领域规则，端到端证据不足

自动测试不能替代以下证据：

- iOS 26.5 模拟器之外的代表性系统运行；
- 真机中文键盘、照片、文件、麦克风和分享；
- VoiceOver 完整闭环；
- 最大辅助字号；
- iOS 17–25 材质降级；
- 大附件备份、恢复和失败回滚；
- 从 V0.1 能力到 V0.2 页面入口的逐项回归。

## 4. V0.2.1 稳定化范围

### 4.1 必须处理

- 附件唯一标识；
- 备份与恢复主线程阻塞；
- 核心闭环真机证据；
- VoiceOver、动态字体和材质降级关键证据；
- 现有测试与当前固定提交的可重复运行。

### 4.2 依据测量决定

- 高频保存优化；
- 大列表或长小票性能；
- 图片解码、缓存和内存占用；
- 启动加载与首屏时间。

### 4.3 不进入 V0.2.1

- V0.3 视觉重做；
- 新信息架构；
- 新产品功能；
- AI、登录、同步或标签；
- 为了“顺手”重写领域层。

## 5. 建议执行顺序

1. 固定审查提交、运行环境和测试结果；
2. 修复附件唯一标识并增加回归测试；
3. 将备份与恢复重任务移出主线程，验证失败回滚；
4. 测量保存、启动、图片和长小票性能；
5. 完成模拟器、代表性旧系统和真机验收；
6. 生成稳定化证据索引并封存提交。
