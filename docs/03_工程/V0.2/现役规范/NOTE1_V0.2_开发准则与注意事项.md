## 1. 文档职责

本文件不重新定义产品需求，而是约束后续开发对话如何把 V0.2 PRD 落成可靠、可测试、可审查的原生 iOS App。

- PRD 回答“为什么做、做什么、对象和结果是什么”。
- 产品设计与交互规格回答“页面必须长什么样、如何动、用哪张图验收”。
- 非回归矩阵回答“V0.1 哪些成熟能力必须保留、如何证明没有丢失”。
- 本文件回答“按什么顺序开发、必须守住哪些边界、如何验证和提交”。
- ADR 回答“重要技术结构为什么这样选择”。
- 当前代码和测试回答“现在实际实现到了哪里”。

产品讨论、PRD 维护任务不自动授权修改代码。只有用户明确开启 V0.2 代码开发的新任务后，才可进入实现。

7. 冻结的 `NOTE1_PRD_V2.6.md` 历史运行态事实；

若用户口述的新要求尚未进入 PRD，开发对话先指出缺口并请求产品对话回写，不凭口头片段扩张代码。待讨论清单只记录非阻塞调整和未来候选，不是代码需求。

## 4. 固定技术与产品边界

- 原生 SwiftUI iPhone App，最低 iOS 17。
- 正式工程：`ios/App/App.xcodeproj`；Scheme：`App`。
- 文字、关系、快照和附件均保存在本机 App 沙盒。
- V0.2 不加入登录、后端、云同步、AI、标签、任务管理、提醒或跨平台版本。
- V0.1 测试数据不迁移；V0.2 内部测试版使用新的本机数据版本。
- 不部署、不上架、不提交 App Store 或 TestFlight；除非用户在独立任务中明确授权。
- 设计变量集中管理；新页面不得散落不可追踪的颜色、圆角、间距、材质和动效常量。
- 新 UI 使用 PRD 确认的标准名称；V0.1 旧称只保留在历史实现与验收记录中。

## 5. 不可破坏的业务不变量

以下规则必须进入数据层约束和自动化测试，不能只靠界面禁用：

1. 灵感是最小内容对象，归入构思集后仍可在“灵感”页面独立找到。
2. 同时最多 5 个构思中的构思集；每组最多 10 条灵感。
3. 一条灵感同一时间最多属于 1 个构思集。
4. 独立灵感左滑只执行“收起”，不删除、不生成小票。
5. 构思集只有在用户确认“结束本轮构思”后，才原子结束当前轮次并生成 1 张构思小票。
6. 一轮严格对应一票；重复回调、快速点击或动画重入不得生成重复轮次或重复小票。
7. 构思小票是不可变快照；之后编辑、删除或重新归入原灵感不得改写旧小票。
8. 回收站只保存独立灵感和构思小票，不保存构思集或构思轮次。
9. 回收站对象从删除时间起保留 30 天；恢复重置删除时间，永久删除必须安全清理引用。
10. 删除构思集时，成员以独立灵感进入回收站；已经生成的小票保持不变。
11. 只有没有任何灵感、小票或回收站对象继续引用附件时，底层附件才允许被删除。
12. 批量操作必须全成或全不成；容量不足、对象冲突或持久化失败时不得部分写入。
13. 构思集默认名称按本机单调递增：`构思集（1）`、`构思集（2）`……；删除后不复用编号。
14. 语音灵感保存原始录音并可同时保存本机转写文字；转写失败不得删除录音，播放失败不得删除文字。
15. 音频附件与语音灵感必须记录来源类型但共用不可变声音资源；两者均可播放，均不得静默上传。
16. 旧小票引用的声音资源不可因原灵感移除附件、删除灵感或重新构思而失效。

## 6. 开发阶段与交付顺序

V0.2 是一个完整版本，但工程必须分阶段实现、验证和提交。

### 阶段 0：技术设计门禁

在修改业务代码前，先形成或接受对应 ADR：

- 灵感、构思集、构思轮次、过程事件和构思小票快照；
- 不可变附件资源、引用关系和安全垃圾清理；
- 回收站 30 天清理与恢复事务；
- 结束本轮、生成小票和约 2 秒撤回的原子事务；
- V0.2 新数据版本与清库策略；
- 批量操作事务；
- PDF 渲染与内存保护；
- 语音灵感临时录音、持久化声音资源、音频附件导入、本机转写、权限矩阵与系统音频会话；
- 一级页面、对象手势和系统返回的协调策略。

ADR 未完成时可以制作不写真实数据的隔离视觉原型，但不得把临时结构直接扩展成生产数据层。

### 阶段 1：数据层

- 建立 V0.2 数据对象、版本和持久化结构。
- 先实现约束、事务、快照、回收站、附件引用和声音资源生命周期，再接页面。
- 为每个失败路径提供明确错误，不静默丢数据。
- 完成单元测试和持久化往返测试后再进入页面框架。

### 阶段 2：一级页面框架

- 建立“灵感 / 卡片预览 / 构思集 / 小票册”四个稳定一级页面。
- 底部导航必须始终提供可见兜底；横滑不能成为唯一入口。
- 先实现页面状态保持、安全区和无障碍结构，再加入复杂动效。

### 阶段 3：核心闭环

完成并联调：

```text
记录灵感 → 卡片预览 → 收起或归入构思集
→ 构思集工作台反复编辑与排序 → 结束本轮构思
→ 生成构思小票 → 在小票册查看 → 继续构思
```

任何按钮都必须有真实结果、失败提示和可验证状态；不提交空壳入口。

### 阶段 4：构思小票与导出

- 先保证一轮一票、快照固定、附件可读和重启可恢复。
- 再实现经典票、胶卷票、模板推荐、出票动画、换票和抽取动效。
- PDF 首版按 PRD 默认 A4 规则实现；真实样本只调整视觉参数，不改变快照语义。

### 阶段 5：搜索、批量与回收站

- 严格按 PRD 页面矩阵显示搜索与选择入口。
- 混合对象搜索结果不得跨类型批量操作。
- 实现恢复、永久删除、清空、自动过期和附件安全清理。

### 阶段 6：整体验收

- 完整自动化测试、模拟器构建和通用 iPhone 构建。
- 真机走通核心闭环、手势、附件、PDF、VoiceOver 和辅助显示。
- 对 iOS 17 最低环境、当前开发环境、小屏和大辅助字号分别保留证据。

## 7. 手势与动效开发规则

- 先建立方向锁定和手势优先级，再调整动画观感。
- 卡片上下翻阅、卡片左滑收起、构思集左滑结束、小票左右换票、下拉抽取和一级页面横滑不得同时提交。
- 卡片预览和小票册的对象手势优先；一级页面切换只使用 PRD 规定的保留边缘区域。
- 系统详情页左边缘返回优先于一级页面切换。
- 键盘、搜索、批量选择、附件预览和 VoiceOver 状态按 PRD 暂停或降级冲突手势。
- 所有隐藏手势必须有可见点击入口或无障碍等价操作。
- 未越过阈值不得显示成功反馈；越过阈值只触发一次触觉。
- 支持“减弱动态效果”和“降低透明度”，不得用长动画阻断继续操作。
- 动效参数必须在真机调整；模拟器截图不能替代手感验收。

## 8. 数据安全与破坏性操作

- 修改存储格式、恢复逻辑、回收站、附件路径或批量事务前必须先写测试。
- 恢复、永久删除、清空回收站和覆盖当前数据必须二次确认。
- 所有路径只使用已经解析和校验的 App 沙盒目标；不得用宽泛目录、未解析变量或递归删除清理数据。
- 失败时优先保持旧数据，禁止出现“界面成功但磁盘未写入”的假成功。
- 不为性能方便破坏旧小票附件快照，也不无条件复制全部大附件。
- 语音灵感保存前使用受控临时文件；取消、失败或事务回滚必须清理临时录音，已成功保存的声音不得被异常清理。
- 语音识别权限失败不得阻断录音保存与播放；麦克风权限失败不得伪造录音成功。
- 不把用户内容、语音、照片、PDF、日志或测试数据上传到外部服务。

## 9. 测试与验证最低要求

每个阶段至少包含与风险相称的自动化测试，并运行相关测试与一次模拟器构建。

### 9.1 截图取证节奏

截图是视觉验收的最小充分证据，不是每个验证步骤的固定动作。编译、单元测试和静态检查不截图；导航、数据和手势行为优先通过 XCTest、可访问性树及状态断言验证。

仅当本轮改动涉及布局、导航栏、手势反馈或视觉样式时，才进行截图验证。同一页面连续修改时，首轮用于建立或校准视觉基线，最终轮用于交付验收；中间轮次除非出现明确视觉风险或自动化/状态证据指向异常，不重复截图识别。默认字号、最大辅助字号和窄屏等视觉场景应合并为一次批量取证。

批量取证按“页面 × 视口 × 数据状态 × 交互阶段”分组，而不是按 ISSUE 或任务逐项截图：同组内所有需要该画面的验收项共用一张稳定态截图，并在证据记录中列出覆盖的 ISSUE/状态；只有页面、尺寸、数据前置条件或交互阶段发生变化时才新增截图。一次语义快照或一段录屏可以同时覆盖同一状态下的多个命中区、导航和手势检查。禁止把“一项任务一张截图”作为默认验收节奏。

优先依据截图元数据、差异结果或明确风险判断是否需要打开图片检查；只有出现明显差异、需与 A 级确认图并排比对，或用户明确要求时，才进行图片识别。此规则不降低本文件或 UI 开发完备性清单规定的批次视觉、无障碍和设备验收门禁：批次结束仍须保留可复核的最小充分证据，并如实列出未验证项。

### 9.2 低成本验证分流

- 仅改数据层、状态机、文案或测试：执行相关 XCTest；不做额外的手动模拟器启动、不截图、不打开图片。
- 仅改编译配置、工程文件或静态安全性：执行构建与静态分析；不截图。
- 改布局、导航、手势反馈或视觉样式：先用自动化/状态断言缩小范围，再按页面批量采集一次基线和一次终态；同一提交的中间修订不重复打开图片，除非元数据、差异结果或失败证据提示视觉回归。
- 截图只保留稳定态和必要视口；先检查尺寸、时间戳和差异摘要，只有命中风险才进行人工图片查看。临时截图放在 `/tmp`，不进入仓库。

### 数据层测试

- 数量上限、单卡单组和默认编号；
- 轮次结束与一轮一票幂等；
- 不可变小票与附件引用；
- 30 天边界、恢复重置、永久删除与垃圾清理；
- 批量事务全成或全不成；
- 语音灵感录音、转写文字、音频附件来源和持久化往返；
- 取消录音、空间不足、转写失败、音频会话中断与临时文件清理；
- 原灵感删除后旧小票声音仍可播放，最后一个引用释放后资源才可清理；
- 损坏数据、写入失败和重启读取。

### 页面与交互测试

- 四页导航状态保持与安全区；
- 卡片翻阅、收起、归入、继续构思和结束确认；
- 手势方向锁定、边缘范围和误触保护；
- 键盘、搜索、选择和弹层关闭；
- 语音灵感录制/停止/取消、音频附件导入、两种声音播放和权限降级；
- 空态、上限、失败态和不可用态；
- VoiceOver 名称、值、顺序和等价操作。

### 小票与导出测试

- 纯文字、长文字、单图、多图、语音、PDF 和混合附件；
- 经典票、胶卷票和模板切换不改数据；
- PDF 分页、超长图片、分享和系统预览；
- 减弱动态效果、低透明度和大辅助字号。

优先使用 XcodeBuildMCP；不可用时才使用 `xcodebuild`。测试报告必须写明设备、系统、测试数量、失败与跳过数量，并区分“编译通过、模拟器运行、真机运行、VoiceOver 实测”四种证据等级。

## 10. Git 与提交规则

- V0.2 开发使用独立 `codex/` 前缀分支，不直接在 V0.1 封存标签上继续堆叠实现。
- 开工前检查脏工作区；现有修改默认属于用户或其他对话，不擅自覆盖、回退或合并。
- 按阶段做小而完整的提交：数据层、页面框架、核心闭环、小票、管理能力和验收资料分开。
- 每个提交应同时包含相关实现、测试和必要文档；不得先提交无法运行的半成品，再寄希望于后续修复。
- 不提交 `DerivedData`、`xcuserdata`、`node_modules`、临时截图、调试日志或包含用户数据的产物。
- 不使用破坏性 Git 命令清理他人修改。
- 未经用户明确授权，不推送远端、不创建发布、不部署、不上架。

## 11. 开发过程中的产品变更

遇到静态稿缺少非关键状态时，可以使用克制、可替换的临时样式继续开发，但要记录在交付报告中。

出现以下情况必须停止相关模块实现，先回到产品对话更新 PRD：

- 对象关系、状态或删除语义不完整；
- 新要求与现有核心手势冲突；
- 需要新增登录、云端、AI、标签或任务能力；
- 同一入口存在两种互斥行为；
- 实现必须改变已经确认的容量、快照或生命周期规则。

只涉及颜色、间距、阈值、阻尼、时长或真实导出参数的调整，可按 PRD 默认值先实现并在待讨论清单记录，不得借机改变业务语义。

## 12. 阶段交付报告格式

每次阶段性交付必须清楚报告：

1. 本阶段完成的用户闭环；
2. 修改的主要文件和数据结构；
3. 自动化测试、构建和运行结果；
4. 模拟器、通用设备构建与真机分别验证了什么；
5. 仍未验证或受环境限制的事项；
6. 与 PRD 的偏差及原因；
7. 下一阶段可以安全开始的前置条件。

不得用“测试通过”代替完整说明，也不得把未执行的真机、iOS 17 或 VoiceOver 验收写成已经完成。

## 13. V0.2 完成定义

只有同时满足以下条件，才能声称 V0.2 完成：

- PRD 中所有 V0.2 必做入口都有真实实现和失败路径；
- 核心闭环从记录到小票、继续构思和回收站可以重启后完整走通；
- 数据不变量、批量事务、快照与 30 天清理都有自动化测试；
- 相关 XCTest 全部通过，模拟器和通用 iPhone 构建成功；
- 目标真机完成主闭环、PDF、附件、手势与无障碍验收；
- 没有把待讨论项、未来 AI、登录或热敏打印误写成已交付；
