# NOTE1 V0.2 产品复盘与 V0.3 产品方向建议

> 状态：V0.3 产品方向参考，未取代现役 PRD  
> 更新日期：2026-08-03

## 0. 文档职责

本文只回答四个问题：

1. V0.2 已经证明了什么；
2. 目前最主要的产品问题是什么；
3. V0.3 应该聚焦什么；
4. 进入开发前还需要验证什么。

页面长相和交互细节由《NOTE1 V0.3 产品设计优化建议》负责；工程风险由《NOTE1 V0.2 源码审查与 V0.2.1 稳定化建议》负责。

## 1. 核心结论

V0.2 的价值不是“功能已经很多”，而是 NOTE1 已形成一条有辨识度的闭环：

`快速记录灵感 → 卡片流回看 → 归入构思集 → 继续构思 → 结束本轮构思 → 生成构思小票 → 在小票册留存`

当前主要问题不是缺功能，而是这条闭环尚未达到最终产品应有的视觉一致性、交互顺滑度和稳定可信度。V0.3 应定位为“产品化与品质版本”，而不是新功能版本。

一句话方向：

> NOTE1 让用户先轻松记下灵感，再用卡片流快速看见它，并把一轮构思留成可带走的小票。

这句话是方向表达，不替代“简单记，快速看”的既有产品主张。

## 2. 产品边界

### 2.1 NOTE1 是什么

- 只服务 iPhone 的本机灵感记录工具；
- 录入压力低，打开后可以立即记；
- 通过卡片流重新遇见和处理灵感；
- 通过构思集聚合当前思考；
- 通过构思小票留下阶段成果。

### 2.2 NOTE1 不是什么

V0.3 不把 NOTE1 扩张为：

- 待办清单或项目管理工具；
- 标签驱动的长期知识库；
- 多人协作或全平台笔记产品；
- AI 自动整理工具；
- 依赖账号、云端或订阅才能使用的服务。

### 2.3 用户假设

以下是需要试用验证的用户假设，不是已经证实的市场事实：

- 经常产生零散想法，但不愿维护复杂笔记系统的人；
- 需要通过图片、语音或文字保存创作线索的人；
- 希望在短周期内重新处理灵感，而不是长期囤积的人；
- 重视隐私、本机保存和低压力体验的人。

V0.3 不应依据这些假设新增功能；应先通过真实试用判断哪类人最容易完成闭环。

## 3. V0.2 已经做对的内容

### 3.1 卡片流建立了辨识度

上下切换卡片、左滑收起、点击进入编辑，使“快速看”成为独立于普通笔记列表的体验。这是 NOTE1 的第一核心亮点，V0.3 不得弱化或替换。

### 3.2 构思集提供了有限聚合

构思集不是分类目录，而是当前集中构思的一组灵感。最多 5 个构思集、每组最多 10 条灵感，帮助产品保持轻量边界。

### 3.3 构思小票形成了阶段成果

一轮构思结束后生成固定快照，使零散灵感有了可回看、可导出、可分享的结果。小票册是第二核心亮点，但它的价值依赖完整的构思过程，不能脱离闭环单独堆砌视觉仪式。

### 3.4 本机与非 AI 边界清楚

文字、附件和快照由本机保存，不登录、不依赖服务端、不使用 AI。这个边界降低了成本和隐私压力，也是 V0.3 的非回归约束。

## 4. 当前主要问题

### 4.1 视觉语言尚未统一

现行功能已经可测，但页面间的标题位置、按钮尺寸、材质亮度、留白、浮动按钮和底部入口仍有不一致，产品看起来更像多个功能模块的组合，而不是一个完整 App。

### 4.2 关键交互的反馈不够稳定

卡片切换、左滑收起、构思集拖入、结束本轮、小票生成和小票浏览都依赖动效与状态反馈。任何一步生硬、误触或遮挡，都会破坏整条闭环。

### 4.3 功能完成与产品完成混在一起

自动测试通过只能证明部分规则与实现可运行，不能证明：

- UI 已达到最终品质；
- 真机手势自然；
- 动态字体和 VoiceOver 可用；
- 附件、备份、恢复和跨系统降级可靠；
- 用户第一次使用就能理解闭环。

### 4.4 当前实现仍有工程稳定化风险

V0.1 与 V0.2 双实现并存、附件预览标识、主线程备份恢复及端到端验证缺口，会增加后续 UI 重构成本。它们应在 V0.3 大改前或并行隔离处理中关闭。

## 5. V0.3 产品目标

### 5.1 主目标

在不增加产品范围的前提下，让现有核心闭环达到可对外测试的产品品质。

### 5.2 三个优先级

1. **统一体验**：四个一级页面属于同一套视觉系统，导航、标题、按钮、材质和反馈一致。
2. **强化闭环**：记录、卡片流、构思集和小票之间的转换自然、清楚、无阻塞。
3. **提高可信度**：数据、附件、备份、恢复、无障碍和跨系统降级有明确证据。

### 5.3 成功表现

V0.3 达到以下结果，才可称为产品化版本：

- 用户无需说明即可完成一次记录和卡片预览；
- 用户能理解“收起”不等于删除；
- 用户能把灵感归入构思集并结束一轮构思；
- 用户能看到、浏览并导出对应构思小票；
- 四个页面在真机上没有遮挡、错位、异常滚动或明显视觉断裂；
- 现有数据和附件能力不因 UI 改造退化。

具体量化阈值需由试用记录产生，不在缺少基线数据时虚构百分比目标。

## 6. V0.3 范围

### 6.1 继续坚持

- 四个一级入口：灵感、卡片预览、构思集、小票册；
- 卡片流上下切换与左滑收起；
- 构思集数量及容量限制；
- 构思轮次与不可变小票快照；
- 本机保存、无登录、无后端、无 AI；
- 全面屏手势和等价可访问操作。

### 6.2 优先优化

- 全局视觉变量与组件一致性；
- 灵感页快速记录和时间流；
- 卡片预览的手势判定、完成反馈与构思集入口；
- 构思集工作台的层级、编辑和结束本轮流程；
- 小票生成动效、小票册浏览和详情；
- 搜索、选择、附件、备份恢复与无障碍的完整状态；
- V0.1 能力的非回归。

### 6.3 明确不做

- 新增 AI、登录、同步、标签、任务或社交能力；
- 重做为三入口信息架构；
- 取消卡片流或横向页面手势；
- 用大量装饰、游戏化或仪式感掩盖核心流程问题；
- 在没有确认图和交互原型时直接整包重写 UI。

## 7. 验证方案

### 7.1 内部产品验收

按四个核心页面和完整闭环逐项验收：默认态、空态、内容态、编辑态、选择态、错误态、键盘态和辅助功能态。

### 7.2 小规模真实试用

先选择少量符合用户假设的试用者，观察而不是引导：

- 是否能立即开始记录；
- 是否会主动进入卡片预览；
- 是否理解构思集；
- 是否愿意结束一轮并查看小票；
- 在哪一步停住或误解。

第一轮目标是发现阻塞，不追求样本统计意义。试用脚本稳定后，再扩大样本。

### 7.3 证据要求

- 真实设备闭环录像；
- 核心状态截图；
- 自动化测试结果；
- VoiceOver 与动态字体检查；
- 附件、备份、恢复和导出结果；
- 问题清单及关闭证据。

## 8. 产品方向关闭条件

以下条件同时满足后，V0.3 产品方向才算可以冻结并进入整包实施：

- [ ] 四个一级页面的结构没有未决冲突。
- [ ] 核心交互状态图已确认。
- [ ] 视觉系统和核心组件已确认。
- [ ] V0.1 非回归能力已映射到验收项。
- [ ] V0.3 范围内与范围外事项已明确。
- [ ] 所有未验证判断均标记为假设或开放问题。
