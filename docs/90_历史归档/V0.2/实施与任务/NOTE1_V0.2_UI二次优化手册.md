## 1. 二次优化目标

本轮不是对现有页面做零散“美化”，而是完成以下四件事：

1. 恢复 V0.1 已确认的 NOTE1 视觉语言：深蓝主色、淡紫背景、浅亮玻璃、克制阴影和稳定圆形按钮。
2. 建立 V0.2 共用的设计变量和组件，消除默认系统蓝、灰色胶囊和页面间尺寸漂移。
3. 按 PRD 真正实现三项核心体验：卡片流、构思集工作台、构思小票与小票册。
4. 让主要手势具有连续跟手过程、清楚阈值、自然回弹和无障碍等价入口。

完成标准不是“能构建”或“按钮能点”，而是功能、视觉、动效、手势和可访问性同时通过本手册第 11 节的验收门禁。

## 2. 依据优先级与边界

### 2.1 依据优先级

发生冲突时按以下顺序处理：

1. `NOTE1_PRD_V0.2.md` 中已经确认的产品结构、状态和交互。
2. V0.1 当前真实运行截图和已有设计变量，用于确定 NOTE1 的品牌视觉语言。
3. 本手册与 UI 问题清单，用于确定实现顺序和验收方式。
4. 当前 V0.2 代码，只代表待优化实现，不反向覆盖 PRD。

### 2.2 明确不做

- 不新增 AI、登录、云同步、任务管理、标签或 PRD 外的信息架构。
- 不因为“更像成熟 App”而复制 flomo、X、小红书或文件 App 的整套视觉。
- 不自行更换品牌色、字体气质、主导航结构或标准名词。
- 不通过压小字号、缩小点击区或隐藏必要入口来解决拥挤。
- 不把 iOS 26 的 Liquid Glass 当作唯一实现；最低 iOS 17 的降级必须同源。

## 3. 必须使用的设计与 iOS 工作方式

开发对话应使用相关 UI skill，但 skill 只提供审计方法和 SwiftUI 实现范式，不是新的设计权威。所有选择仍需由 PRD、V0.1 对照图和本手册约束。

建议按以下顺序使用：

1. `product-design:audit`：每轮先把参考图与当前同尺寸截图并排审计，确认差异后再改。
2. `build-ios-apps:swiftui-ui-patterns`：建立可复用顶部栏、底栏、输入工具栏、叠卡与页面状态结构。
3. `build-ios-apps:swiftui-liquid-glass`：iOS 26 使用可交互玻璃；iOS 17–25 提供半透明材质降级。
4. `build-ios-apps:ios-simulator-browser`：对每个关键状态实际操作、截图和录屏，不只看 Preview。

以上四项从“建议”升级为二次优化阶段的执行门禁：开发对话在开始每个 P0 阶段前必须读取对应 skill，阶段结束后必须用审计与模拟器证据自查。skill 负责提供实现和审计方法，不能代替 NOTE1 的产品判断，也不能把通用模板风格带入项目。

使用限制：

- 不允许 skill 根据通用趋势自由生成新主题。
- 每次调整必须指出它解决了哪个问题 ID，以及依据哪一张 V0.1 或 PRD 证据。
- 每完成一个阶段，先生成同视口对照图；视觉差异未关闭时，不进入下一阶段。
- 不以“自动化测试通过”替代视觉通过；数据测试、手势状态测试和视觉验收是三条并行门禁。

## 4. 设计系统先行

### 4.1 语义颜色

集中维护颜色变量，页面中不得散落系统 tint 和临时 RGB：

| 语义变量 | 建议基线 | 用途 |
| --- | --- | --- |
| `noteInk` | V0.1 深蓝，约 RGB 0.035 / 0.105 / 0.205 | 主标题、正文、关键图标、选中态 |
| `noteSecondaryInk` | 蓝灰，约 RGB 0.48 / 0.54 / 0.67 | 时间、说明、禁用状态 |
| `noteBackgroundTop` | 约 RGB 0.965 / 0.965 / 1.0 | 背景渐变上端 |
| `noteBackgroundBottom` | 约 RGB 0.92 / 0.925 / 0.995 | 背景渐变下端 |
| `noteGlassFill` | 浅亮且带背景透感 | 默认玻璃按钮、底栏、输入栏 |
| `noteSelectedFill` | 深蓝或受控强调玻璃 | 当前一级入口和主操作 |
| `noteDanger` | 系统语义红的受控版本 | 删除确认，不参与品牌主色 |

规则：

- 默认态保持浅亮，不得发灰；用户按下时才出现轻微暗化或饱和度变化。
- 禁止把系统亮蓝作为 NOTE1 主色；链接、选择和新增也应使用语义颜色。
- 蓝灰仅用于次级信息，不用于大面积底栏背景。

### 4.2 布局度量

建立共享度量，避免每个页面独立写固定 padding：

- 页面水平边距：统一变量，按屏宽允许轻微自适应。
- 顶部栏按钮：视觉直径约 46–52pt，点击区不得小于 44 × 44pt。“46–52pt”只作为初始调校范围，不是必须做成厚重白色大圆；视觉直径、内部图标和外部点击区必须分别控制，并与 V0.1 同尺寸截图比较。
- 顶部栏左右操作与屏幕边缘、状态栏的关系固定；四个一级页面切换时不跳动。
- 底栏高度、底部安全区、新增按钮直径及其与底栏的间距由同一布局容器计算。
- 正文、元数据、标题使用 Dynamic Type 语义字体，不使用大量硬编码小字号。

### 4.3 组件清单

二次开发至少建立并复用以下组件；命名可按工程约定调整：

- `V02TopBar`
- `V02GlassIconButton`
- `V02BottomNavigation`
- `V02FloatingComposerButton`
- `V02PaperCard`
- `V02CardDeck`
- `V02CollectionPickerTray`
- `V02TicketClip`
- `V02ReceiptPaper`
- `V02SearchScopeBar`
- `V02ToastBar`

最终核心页面不得直接使用 `.buttonStyle(.bordered)` 或 `.borderedProminent` 暴露系统默认外观。系统组件可以保留语义和行为，但视觉必须通过 NOTE1 组件封装。

## 5. 全局骨架优化

### 5.1 底部一级导航与新增按钮

必须先关闭 UI-001、UI-002：

- 底栏保持淡紫背景上的浅亮玻璃，不使用灰色实底。
- 选中项使用深蓝底或深蓝图标形成清楚状态；未选中项仍可读，但不抢主操作。
- 图标与文字不能继续采用当前过小的 16pt / 11pt 组合。
- 新增按钮独立悬浮在内容区与底栏之间，不压住“小票册”入口，也不与选中态合并。
- 新增按钮的可点击区域可以接近底栏，但视觉圆形不得进入任一一级入口的图标与文字区域；需在最窄支持机型和最大辅助字号下复验。
- 使用一个容器或 `safeAreaInset` 同时布局底栏和新增按钮，删除两套互不相关的固定 bottom padding。
- 键盘、Sheet、搜索和批量选择出现时，明确底栏与新增按钮谁隐藏、谁上移，不能交由偶然布局决定。

### 5.2 顶部栏

必须关闭 UI-003：

- 首页左右按钮使用同一圆形玻璃组件，尺寸、图标、边距和按下态一致。
- 默认态保持 V0.1 浅亮玻璃；按下态轻微变暗或缩放，不变成刺眼纯白。
- 中间 `NOTE1⌄` 使用深蓝，不使用默认亮青蓝。
- 构思集、小票册和卡片预览的一级页面名称居中；右上操作使用同一视觉组件。首页继续使用左侧统一入口、居中 `NOTE1⌄` 和右侧搜索的稳定关系。
- “选择”使用用户确认过的勾选图标，不使用孤立蓝色文字。

### 5.3 Liquid Glass 与降级

- iOS 26：同一区域多个玻璃控件应放入 `GlassEffectContainer`；可点击控件使用 `.glassEffect(...interactive())`。
- iOS 17–25：使用统一的 material、描边和阴影降级，不得变成另一套灰色 UI。
- `Reduce Transparency` 开启时提高实色填充和对比度，不保留低可读的模糊背景。
- 不为追求玻璃感叠加多层白色和强阴影；NOTE1 的玻璃应轻、冷、克制。

## 6. 页面级实施要求

### 6.1 灵感首页

- 保留“按更新时间混合显示全部灵感”的产品结构。
- 灵感卡片本体点按进入编辑，移除常驻“编辑”蓝色胶囊。
- 短内容紧凑展示，长内容显示合理摘要；不得只显示三行后在页面下方留下大片无意义空白。
- 时间与“构思集 · 名称”属于次级信息，保持可读但不与正文争夺注意力。
- 近期成果摘要可以轻量存在，但不得弱到像禁用文字，也不能压过快速录入。

### 6.2 录入面板

- 从“纵向表单”改为底部锚定的聊天式录入面板。
- 正文是主要区域；附件、录音和发送/保存形成稳定工具栏。
- 明确文本占位提示和保存可用状态；禁用状态仍需可辨识。
- 使用 `FocusState`、`safeAreaInset` 和交互式键盘收起，覆盖短文、长文、多附件和录音状态。
- Sheet 出现时不继续展示可误触的底栏和全局新增按钮。

### 6.3 卡片预览

视觉与状态验收统一使用：`docs/02_设计/V0.2/视觉基线/20-已确认-卡片预览与构思集一次拖拽状态图.png`。

- 使用 `V02CardDeck`：当前卡片完整显示，前一张和后一张各露出一小部分纸边。
- 前后层只能露出没有可读正文的纸边；严禁把完整相邻卡片以透明方式叠在当前卡片下方。
- 日期、正文与操作保持清楚层级；普通灵感正文不得再与构思集标题同等大。
- 上下拖动时，卡片和目标纸边由同一进度连续变化；越阈值切换，否则回弹。
- 左滑“收起”只在方向锁定且越阈值后生效，避免上下滑误触。
- 上一张、下一张保留无障碍操作，但不再以三个系统灰胶囊占据视觉中心。

### 6.4 快速归入构思集

- 卡片预览下方恢复构思集圆形入口，并显示所有构思中卡片总数角标。
- 总角标不是构思集数量。
- 长按按钮后按容量动态显示一个或两个拓展目标：0 个构思集只显示“新建构思集”，1–4 个显示“新建构思集 / 归入现有构思集”，5 个只显示“归入现有构思集”。
- 双目标分别位于圆形入口左上与右上，向外轻微倾斜、柔和悬浮；不得绘制弧线、虚线、箭头或任何按钮间连接关系。
- 拖动时按钮本体不跟手；用户只拖拽到操作类型并松手，不继续拖到具体构思集。
- 松手后打开对应的点击式面板：新建面板，或显示名称和 `当前数量/10` 的现有构思集列表。
- 达到 10 条的构思集不可接收；点按后提示“当前版本每个构思集只支持 10 条灵感”，归入失败且数据保持不变。
- 手指离开拓展目标立即取消高亮，目标外松手绝不打开面板、误创建或误归入。

### 6.5 构思集总页面与工作台

视觉与状态验收统一使用：`docs/02_设计/V0.2/视觉基线/21-已确认-构思集总页与工作台状态图.png`。

- 总页面只展示“构思中”的构思集；“构思历程”使用右上独立入口。
- 页面标题居中；新建构思集使用与灵感页一致的右下角悬浮“+”，不为按钮预留空白模块。
- 空态仍显示悬浮“+”；达到 5 个时保留按钮，点按后从页面下方短暂显示 PRD 规定提示。
- 点入构思集后直接进入叠卡工作台，不先进入 CRUD 管理页。
- 工作台与卡片预览复用纸张、叠卡、正文和切换动效。
- 工作台可以使用系统 Sheet/NavigationStack 承载返回与系统手势，但大面积背景、工具栏按钮和纸张必须保持 NOTE1 主题，禁止退回纯白系统管理页。
- 支持原位编辑、上下切换、位置提示、卡片概览与排序；最多 10 张。
- 非键盘态右下悬浮“+”新增组内卡片；键盘编辑态隐藏该按钮，收起键盘后恢复。
- 改名、移出、删除和结束本轮构思进入明确的二级操作区，不在列表卡片中全部平铺。

### 6.6 构思小票生成

- A 级动效关键帧为 `docs/02_设计/V0.2/视觉基线/23-已确认-结束本轮构思与小票生成关键帧.png`。
- 用户确认“结束本轮构思”后先原子保存构思轮次和小票，再播放视觉结果。
- 动画阶段固定为：确认 → 夹口准备并露出纸头 → 连续出纸且内容逐步显现 → 在屏幕内停止收束。
- 停止收束后才显示“查看小票 / 返回 / 撤回（约 2 秒）”；这些是短时结果操作，不是小票册常驻工具栏。
- 同一次动作只生成一张小票，只触发一次结果反馈和一次轻触觉。
- 动画被中断、App 退后台或用户开启减弱动态效果时，不得重复生成。
- 减弱动态效果下使用短距离展开与淡入代替大位移动画。

### 6.7 小票册与小票详情

- A 级实现目标为 `docs/02_设计/V0.2/视觉基线/22-已确认-小票册档案导轨与更多菜单状态图.png`；不得用早期短卡或原始方案图替代。
- 根页面使用票据夹构图：顶部票据夹/钉位、当前小票、后方纸张露边。
- 左右滑动跟手换票；向下拉动跟手抽取；点按提供等价详情入口。
- 根页面以自然高度长条纸张显示完整小票内容，页面可纵向滚动；不得退化为固定高度摘要或短白卡。下拉抽取从夹口/顶部把手触发，或只在当前票已经滚动到顶部且方向明确时触发，避免与长票阅读冲突。
- 页面标题居中，不显示右下全局新增灵感按钮；右上固定为搜索和三点“更多”。选择、模板切换、导出 PDF、分享、复制、查找和删除从“更多”菜单进入。
- 根页与详情不在底部常驻操作栏；详情顶部使用返回、居中标题与三点“更多”，并承接附件真实预览和来源关系。
- 经典票与胶卷票混合浏览，不强行分区排序；模板应由内容自动推荐但允许用户切换。
- PDF、照片、语音等附件在小票上显示可识别摘要；原文件从详情进入预览。
- 批量导出、分享、删除属于选择模式，不作为每张票的常驻大按钮。

### 6.8 搜索

- 完整搜索页的输入框放在顶部，范围筛选紧邻其下，结果列表自然向下展开。
- 从灵感、构思集或小票册进入时显示当前搜索范围。
- 清除、取消和范围切换保持同一视觉系统，不使用零散系统蓝文字。

### 6.9 设置与回收站

- 保留原生列表的可用性，但统一顶部按钮、背景和主题色。
- 设置页版本必须显示真实 V0.2 构建版本。
- 回收站保留“超过 30 天自动删除”的规则说明；恢复和永久删除使用清楚的选择模式。

## 7. 动效与手势模型

所有核心手势不得只在 `onEnded` 后突然跳转。建议每类交互维护一个归一化进度 `0...1`：

1. `onChanged` 更新方向锁定、位移和进度。
2. 进度同时驱动卡片位置、纸边展开、透明度、阴影和目标高亮。
3. 越过阈值后完成；未越过时使用受控弹簧回到初始状态。
4. 触觉只在阈值首次越过时或结果完成时发生一次。
5. 本次手势一旦锁定横向或纵向，结束前不切换方向。

需要分别调试并录屏：

- 一级页面整页横滑。
- 卡片上下切换。
- 独立灵感左滑收起与左边缘右滑返回。
- 卡片归入构思集的按住上拖。
- 构思集结束本轮构思。
- 小票左右切换与向下抽取。

参数不能只在 iPhone 17 Pro 模拟器上凭感觉确定；至少补一台较小尺寸模拟器和一台实体 iPhone。

## 8. 推荐实施顺序

### P0-A｜设计系统与全局骨架

1. 提取语义颜色、字号、间距、圆角、阴影和材质。
2. 建立顶部栏、底栏、圆形按钮、悬浮新增按钮。
3. 修复新增按钮重叠、顶部按钮比例、默认系统蓝和灰色底栏。

## 9. 开发中的禁止项

- 禁止一口气重写所有页面后只提交最终截图；必须按 P0-A、P0-B、P0-C 分阶段对照。
- 禁止用更多白色、更多模糊和更强阴影掩盖层级问题。
- 禁止把默认系统按钮临时保留为“后续再美化”的最终提交。
- 禁止用固定屏高、固定底部 padding 或单一机型坐标解决安全区。
- 禁止为了动画牺牲数据原子性、手势防误触或减弱动态效果支持。
- 禁止只验证模拟器点击路径，不验证跟手过程、取消过程和边缘手势竞争。
