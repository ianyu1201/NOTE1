# NOTE1 文档总入口

> 更新日期：2026-08-11

NOTE1 只保留三份现役基线，使用稳定文件名就地更新。当前版本写在文件内部和项目状态中，旧版本内容由 Git 历史追溯，不再为每个版本建立一套平行文档目录。

## 唯一现役基线

1. 产品：[`01_产品/NOTE1_PRD.md`](./01_产品/NOTE1_PRD.md)
2. 设计：[`02_设计/NOTE1_产品设计与交互规格.md`](./02_设计/NOTE1_产品设计与交互规格.md)
3. 工程与验收：[`03_工程/NOTE1_开发与运行验收基线.md`](./03_工程/NOTE1_开发与运行验收基线.md)

稳定项目定位见 [`00_项目治理/PROJECT_BRIEF.md`](./00_项目治理/PROJECT_BRIEF.md)，当前阶段、版本和门禁见 [`00_项目治理/PROJECT_STATE.md`](./00_项目治理/PROJECT_STATE.md)，正式任务登记见 [`00_项目治理/THREAD_REGISTRY.md`](./00_项目治理/THREAD_REGISTRY.md)。治理文件只保存定位、状态和指针，不重复定义产品需求。

## 裁决顺序

1. 用户在当前正式产品任务中的最新明确确认；
2. 现役 PRD；
3. 现役产品设计与交互规格；
4. 现役开发与运行验收基线；
5. 已接受 ADR；
6. 当前代码、测试和证据只说明现状，不自动覆盖产品目标。

## 目录职责

| 目录 | 职责 | 是否定义现役需求 |
| --- | --- | --- |
| `00_项目治理/` | 项目简报、状态和任务登记 | 否 |
| `01_产品/` | 唯一完整 PRD | 是，定义产品 |
| `02_设计/` | 唯一设计与交互规格 | 是，定义页面和交互 |
| `03_工程/` | 唯一工程、非回归与运行验收基线 | 是，定义实施与证据 |
| `04_技术决策/` | 已接受 ADR | 只定义长期技术决定 |
| `../evidence/` | 按版本保存确认视觉、开发证据和运行证据 | 否 |

## 新文件规则

- 产品、设计和工程决定直接更新对应现役基线，不新增 `V0.x/` 子目录或并行建议稿。
- 当前状态只写入 `PROJECT_STATE.md`，任务身份只写入 `THREAD_REGISTRY.md`。
- 新截图、录屏和日志进入 `evidence/<版本>/<证据身份>/<批次>/`，并更新对应 README 或 manifest。
- V0.3 开发批次统一登记在 [`../evidence/V0.3/MANIFEST.md`](../evidence/V0.3/MANIFEST.md)；最终验收必须使用固定候选重新取证。
- 不在仓库根目录新增一次性计划、临时截图、构建缓存、`.DS_Store` 或旧副本。
- 移动文件后必须修正全部引用；移动源码前必须核对 Xcode target，目录治理默认不移动源码。
