## 0. 文档职责

本文定义 V0.4 页面结构、状态、导航、手势结果、适配、无障碍与视觉基线。V0.3 未被 V0.4 明确取代的功能规则继续作为非回归来源。产品对象和业务边界以 V0.4 PRD 为准；实现与证据要求以 V0.4 工程与运行验收基线为准。

当前代码与模拟器运行态只说明“现在是什么”。用户明确确认的四页、颜色、组件、状态方向及小票生成与阅读分镜已保存到 `02_设计/视觉素材/`。图片示例数据不进入实现，分镜也不能反推未写入本规格的动画参数。

## 1. V0.4 设计目标与当前外观

### 1.1 目标

NOTE1 应呈现安静、轻盈、清楚、有触感的本机记录工具。用户第一眼看到内容和当前动作，而不是管理系统、表单或工具栏。

一句话视觉身份：**冷静的数字索引，以近黑梅墨留下克制但可识别的痕迹。**

明确不是什么：不是整屏淡紫、亮紫品牌、蓝紫渐变、全局纸张/手账、复古票据、霓虹光效或厚重悬浮卡片系统。

### 1.2 当前实现外观（非 V0.3 视觉基线）

- 冷调淡紫背景作为全局画布；
- 深海军蓝用于正文、图标和当前选中状态；
- 浅亮玻璃用于导航、菜单和轻量浮层；
- 纸张用于灵感卡片和构思工作台；构思小票使用独立的黑白热敏票据语言；
- 默认状态不发灰，不使用刺眼纯白或默认系统蓝大按钮；
- 阴影只表达纸张层级，不制造厚重悬浮白块；
- 使用系统语义字体和 Dynamic Type，不引入装饰性字体。

该外观只说明 V0.3 当前实现状态。顶部框架、纸张边界、按钮材质、图标粗细、排版节奏与动效收束如何形成贯穿四页的 NOTE1 身份，统一进入 V0.4 重新讨论和确认。V0.3 不使用当前截图、参考图或代码外观反推已批准视觉基线。

### 1.3 V0.4 已确认语义颜色：梅墨雾白

| 语义 | V0.4 基线 | 用途 |
| --- | --- | --- |
| `noteInk` | 近黑梅紫，约 `#2A1725` | 主标题、正文、关键图标、选中态和浮动“+” |
| `noteSecondaryInk` | 中性灰紫，约 `#716A72`；与实际承载表面对比度不低于 `4.5:1` | 时间、说明、附件摘要与非关键图标 |
| `noteCanvasTop` | 冷雾白，约 `#FAF9FB` | 背景上端与大面积主体 |
| `noteCanvasBottom` | 极浅灰梅白，约 `#F3F1F4` | 背景下端；不得表现为明显紫色渐变 |
| `noteDivider` | 淡灰紫，约 `#DED9E0` | 分隔、克制边界与非颜色唯一状态提示 |
| `notePaper` | 冷调近白，与画布通过边界和阴影区分 | 卡片预览与必要内容表面 |
| `receiptPaper` | 中性近白，不带黄色或复古暖调 | 构思小票纸面 |
| `receiptInk` | 黑色或石墨黑 | 构思小票票头、正文、统计和分隔线 |
| `noteGlass` | 基本无色的原生 Liquid Glass | 顶部按钮、底部导航、菜单与轻量浮层 |
| `noteSelectedGlass` | 极浅梅雾，约 `#EEE7EC` 的低透明度染色 | 只用于选中镜片、按压与关键反馈 |
| `noteSelected` | `noteInk` | 当前一级入口、明确主操作和统一浮动“+” |
| `noteDanger` | 受控系统红 | 永久删除与破坏性确认 |

- 冷雾白承担约 85% 的可见面积；近黑与中性墨色约 10%；梅紫交互强调约 5%，不得把所有玻璃和大面积画布染紫；
- Liquid Glass 默认从背后画布取色，只有选中、按压和明确主动作允许极轻梅紫染色；
- 浮动“+”四页统一为近黑梅紫底与白色加号；小票纸面不读取梅紫主题色；
- 不允许系统 tint 漂移成亮青蓝、亮紫、粉红或酒红；
- 颜色必须通过现役代码变量实现，表中十六进制仅用于识别与对照，不鼓励页面内硬编码。

### 1.4 尺寸、间距与命中

- 基准视口为约 393×852 的主流 Pro 尺寸，同时在约 368×800 的窄视口复验；
- 四个一级页共用同一顶部组件：高度 56pt、水平安全边距 22pt，中间统一显示 `NOTE1`；
- 顶部圆形按钮实际命中区为 48×48pt，可见材质直径 46pt，同侧按钮间距 4pt，四页使用同一阴影与按压反馈；
- 灵感与小票册的中间标题保留页内菜单能力，但指示符独立于 120pt 标题容器布局，不得将 `NOTE1` 推离屏幕中心；
- 所有交互目标不得小于 44×44pt，Dynamic Type 放大时优先增加容器高度；
- 页面水平安全边距使用共享变量，标题、纸张和底栏不得各自漂移；
- 四个一级页的首屏可见内容统一从顶部栏下方 8pt 开始，主内容或主纸张水平外沿为 22pt；
- 需要表达叠纸时，后层只用 5pt/9pt 偏移露出，不得通过增加容器水平 padding 缩窄最前纸张；
- 同级内容遵循约 8pt 节奏，页面分区使用约 16/24pt 节奏；
- 不为对齐单张截图散落互不关联的固定 padding 或固定高度。

### 1.5 Mononote 参考边界

2026-08-09 根据 [Mononote: One Note 官方 App Store 页面](https://apps.apple.com/us/app/mononote-one-note/id6788222857) 与官方截图，当前参考方向包含：

- 打开后立即呈现当前主要对象，不先展示管理面板；
- 一个屏幕只有一个最明确的主操作，次级能力收入克制的入口；
- 大留白、简洁字号层级、大命中区和明确的按压状态，降低认知负担；
- 完成主要操作后结果立即明确，不让用户猜测是否已保存。

Mononote 只作为上述极简设计方法参考；NOTE1 维持四页结构和现有启动入口，不照搬单条笔记模型、启动即编辑、底部中心 Done、锁屏常显、小组件或 Live Activity。

## 2. 全局页面框架

### 2.1 一级页面

固定顺序：

`灵感｜卡片预览｜构思集｜小票册`

- 四个入口等宽，命中高度不低于 44pt；
- 选中项使用近黑梅紫图标/文字与极浅梅雾镜片，未选中项使用近黑梅紫或灰紫线性图标；
- 小票册入口采用已确认的[“微型票面”参考](视觉素材/NOTE1_V0.4_小票册入口_微型票面_确认.png)：优先使用系统可用的直立 `receipt` 语义图标，票头与两条打印线清楚、票尾仅轻微缺口；选中态只增加近黑梅紫墨色和极浅纵向梅雾光晕，不使用电影票轮廓、票夹或独立胶囊；
- 底部导航保持稳定，不随页面内容跳动；
- 页面内容通过安全区为导航留出空间，不用额外大块空白避让；
- 点击底部入口始终是可见、等价的兜底路径。

### 2.2 浮动新增按钮

- 灵感、卡片预览、构思集和小票册四页均显示；
- 四页使用同一右下位置、光学尺寸、近黑梅紫底、白色加号、材质和按压反馈；
- 四页点按后都进入“新增灵感”，不得用于新增卡片、构思集或小票；
- 覆盖在内容层之上，只避开底部导航、Home Indicator、键盘和安全区；
- 不为按钮预留独立槽位、固定空白行或大块空白；
- 搜索、选择、录入、附件选择、详情和键盘编辑状态下隐藏。

### 2.3 顶部框架

- 四个一级页面使用同一套顶部槽位：左上全局菜单、中间页面标题、右上次级入口与最右搜索；
- 四页中间标题文案均为 `NOTE1`，不再分别显示“构思集”或“小票册”；
- 一级页不得在共享 `NOTE1` 顶部下再重复显示“灵感”“卡片预览”“构思集”或“小票册”大标题；当前页由底部选中入口及内容首分区共同表达；
- 左上全局菜单在灵感、卡片预览、构思集和小票册展开后均只显示“回收站”与“设置”，顺序、图标和文案完全一致；
- 搜索按钮在四页始终占用最右槽位，不因历史或更多按钮出现而换位；
- 历史按钮在四页始终常驻并紧贴排在搜索左侧；四个按钮的图标、文案、命中区和可访问名称一致，均打开同一全局历史中心；
- 灵感页 `NOTE1` 保留排序入口，小票册 `NOTE1` 保留模板/导出等页内菜单；卡片预览与构思集使用静态 `NOTE1`；
- 页面级的模板、导出、分享和删除等操作不占用最右搜索槽位，收入对象或页面内的次级菜单；
- 同类按钮跨页面保持尺寸、材质、图标粗细和按压反馈一致。
- 搜索、历史、回收站、设置使用同一二级页面顶部几何：56pt 高度、22pt 水平边距、48pt 命中区和 46pt 可见玻璃按钮；标题独立居中，不因左右动作数量不同而偏移。
- 二级页只统一框架，不抹平语义：搜索保留取消/选择，历史保留返回，回收站与设置保留关闭，回收站更多仍位于右侧。
- 记录灵感与构思工作台等对象页沿用同一 56/48/46pt 顶部几何和同源玻璃按钮，但保留对象名称与成员数量等上下文，不改成 `NOTE1` 品牌标题。
- 构思工作台即使左侧只有返回、右侧同时存在结束与更多，也必须按屏幕中心放置集合名和 `N 条灵感`，不得按左右动作剩余空间做视觉居中；不显示 `/10` 或满额状态。
- 记录页的取消、有未保存内容时的放弃确认与明确保存保持可达；工作台返回前持久化当前编辑，结束仍先确认，更多菜单保持概览与排序、改名和删除构思集。
- 保存及工作台底部附件、移出、更多属于上下文操作标签，最大辅助字号限制到 1.25 倍并保留至少 44pt 命中；灵感正文和编辑内容不使用该上限，继续完整响应 Dynamic Type。
- 灵感编辑、小票详情、附件管理、搜索构思集详情、历史详情、本机隐私说明和概览排序均属于 NOTE1 自有详情页，继续使用共享 56/48/46pt 顶部框架；同一语义使用同一图标、尺寸、材质和按压反馈。
- 自有详情页只统一表现，不抹平动作：全屏编辑与历史详情使用返回，独立模态详情使用关闭，附件管理保留完成与添加，概览排序保留关闭与编辑/完成，小票详情保留返回与更多。
- 小票页内查找与其他上下文操作条的图标、输入和关闭文案最大 1.25 倍；票面、灵感正文、隐私正文和详情内容继续完整响应 Dynamic Type。
- 嵌套详情、附件预览或导出层出现时，后方页面及其顶部按钮必须退出可访问性焦点树，关闭后恢复；Quick Look、照片/文件选择器和系统分享属于系统界面，不套用 NOTE1 自有顶部。

### 2.4 页面横滑

- 四页按固定顺序切换，首尾不循环；
- 灵感和构思集总页在未命中内容控件时可整页横滑；
- 卡片预览和小票册只从保留边缘发起一级页切换，对象手势优先；
- 手势方向和距离明确后才接管页面切换；
- 未过阈值回弹，不出现半页停留或误触发对象操作。

## 3. 通用组件与反馈

### 3.1 纸张与玻璃

- 纸张层承载正文、图片和附件摘要；
- 同一页面的顶部下方、主内容宿主、卡片下方操作区与底部安全区必须读取同一个 `canvas` 语义画布；允许玻璃产生连续折射，但不得出现可见的水平硬分界、矩形色块或上下两段不同底色；
- 卡片与小票的分页/拖拽宿主、相邻对象容器及安全区外延必须透明或使用同一 `canvas`，中间帧不得暴露全屏 `notePaper` / `receiptPaper` 矩形底板；卡片和小票只在对象自身几何内绘制纸面、0.5–1pt 边界和极轻阴影，不为对象周围或下方增加全宽底色带；
- Liquid Glass 只承载导航、顶部控制、上下文按钮、菜单、临时反馈和操作面板；普通内容行不逐项玻璃化；
- 默认玻璃基本无色，使用约 0.5–1pt 的淡梅灰光学边界与极轻、紧凑的梅灰阴影；不得表现为不透明白色塑料；
- 选中态使用克制的半透明梅雾镜片，不使用实色胶囊，不拆分连续底栏；
- 减少透明度开启后使用不透明冷雾白表面和清晰梅灰边界，保持原几何、层级、命中区与状态关系；
- iOS 17–25 不支持较新材质时，降级到系统可用材质，不改变层级、可读性和命中区域。

### 3.2 按钮

- 默认态保持清楚和浅亮；
- 顶部圆形按钮的可见直径为 46pt、命中区至少 48×48pt；菜单、历史、搜索跨页使用同一材质、边界、阴影和图标粗细；
- 按下统一缩放到约 0.97，玻璃密度与边界略增强，释放后回到默认态；不弹跳、不发光；
- 禁用态降低墨色与图标对比但仍保持对象边界；加载态保留按钮尺寸并使用非阻断进度反馈；
- 四页浮动新增使用近黑梅紫圆形表面、白色加号和紧凑阴影；VoiceOver 焦点使用系统焦点表达，不永久增加第二圈装饰；
- 破坏性操作使用红色语义色，并在执行前确认；
- 图标按钮必须提供可访问名称；仅靠手势可达的能力必须有点按或 VoiceOver 等价入口。

### 3.3 临时反馈

- 收起、归入成功、结束撤回和保存失败采用不阻断主路径的短时反馈；
- 提示与触发对象保持空间关联，不固定占据内容区域；
- 错误发生后保留当前内容、选择和操作上下文，不误关闭面板。
- 成功提示同时提供适用的“撤回”；中性信息和破坏性确认分别使用语义图标/文字，颜色不得成为唯一信号；
- 临时反馈优先使用文字层级、图标和细分隔，不使用大面积语义色填充或厚重阴影。
- 小票完成落盘后在屏幕最上方显示非阻断提示“已生成并保存小票册”；提示只公告一次，不附带“查看”“保存”或“打印”动作，不遮挡小票本体。

### 3.4 选择面板与上下文胶囊

- “归入构思集”使用文件夹图标加完整文字的共享胶囊；默认、按下、禁用和加载状态保持相同几何；
- 构思集目标行使用简单内容表面，不逐行使用 Liquid Glass；正常、选中、新建入口和真实保存错误通过文字、图标与边界区分；
- 选中行使用极浅梅雾背景与明确选中语义；任何目标都不得因成员达到旧 10 条边界变成“满额”或不可点击；
- 面板关闭、取消或失败不改变当前卡，覆盖时后方控件退出可访问性焦点树。

## 4. 分页面规格

### 4.5 结束本轮与小票生成

- 构思集级“结束本轮构思”先进入确认，不直接改写数据；确认页标题固定为“已结束本轮构思”，其下只显示“构思时间、灵感数量、附件数量”三项左右对齐摘要，删除构思集/轮次副标题与说明段；唯一主动作固定为“生成小票”，下方次级动作固定为“取消”；
- “已结束本轮构思”只作为结果导向的界面标题，不能驱动提前提交。取消返回原工作台，成员、顺序、内容和轮次状态不变；
- 点按“生成小票”一次即原子化结束当前轮次、生成不可变小票并保存到小票册。只有持久化成功后才进入完成动效；失败时保留原轮次、成员、顺序和内容，在原确认上下文显示错误与重试，不显示成功提示；
- 数据提交成功后的打印动效只是结果呈现，不再提供第二次“打印”、单独“保存”或“查看小票”按钮。播放中若 App 暂停或进入后台，恢复时直接落到已保存的小票缩略图，不重复生成或保存；
- 打印机位于共享顶部下方的界面上部并保持稳定；小票在打印机后层，纸张上缘必须穿过机身正面的窄吐出口，机身前沿遮住纸张与机器的连接处；先从该吐出口露出小票尾部，再连续显露纸面与内容，不得让纸张从机身底边凭空出现，文字必须始终附着在纸面内；
- 推荐正常动效节奏为：按下/提交反馈约 `120ms`；从尾部到完整出票约 `1400ms`，低加速度 `easeInOut`；停顿约 `80ms`；完整小票再从后层向上移动并由约 `0.84` 放大至 `1.0`，以约 `420ms easeOut` 收束到前景可点按缩略图；不得增加弹簧反复回弹、庆祝粒子或对勾主视觉；
- 结果态在屏幕最上方显示“已生成并保存小票册”，中央只保留可点按的小票缩略图，底部只保留“返回构思集”。现有“结束撤回”能力不得作为结果态新增按钮，可从既有构思上下文的等价入口继续访问；
- 点按小票缩略图，以约 `360ms easeInOut` 从当前位置扩展到铺满手机可用阅读区；根页底部导航、生成动作和结果按钮同步淡出并退出可访问性焦点树。全屏阅读使用纵向滚动承载完整内容；
- 开启“减少动态效果”时跳过物理打印与缩放：使用 `180–220ms` 淡入及不超过 `8pt` 的短位移直接呈现缩略图；进入全屏阅读使用不超过 `200ms` 的交叉淡化，业务结果、顶部提示和返回路径不变；
- 开启“减少透明度”时顶部提示改为不透明冷雾白与清晰梅灰边界，不改变位置、文案和命中关系；
- VoiceOver 不逐帧朗读打印过程；保存成功后只公告一次“已生成并保存小票册”。缩略图名称包含小票标题或构思轮次，提示为“双击查看完整小票”；进入阅读后焦点移动到票头，正文按标题、分区和条目组织语义。
- 生成流程前四个分镜状态继续显示单一连续 Liquid Glass 四入口底栏，固定选中“构思集”；“卡片预览”使用双叠卡图标，“构思集”使用文件夹图标，“小票册”使用票据图标，图标不得重复或混淆。进入全屏读票后底栏隐藏；

## 7. 适配与无障碍

- 在已确认的“梅墨雾白”视觉基线中，核心内容必须保持可读，不以固定像素高度截断动态字体；
- 关键正文允许纵向滚动，主要操作不因字号增大消失；
- 图标按钮命中区不低于 44×44pt；
- 语义标签描述对象和动作，不朗读装饰图层；
- 手势动作提供按钮或 VoiceOver 自定义操作；
- 焦点顺序按顶部、内容、主要动作、底部导航排列；
- 临时提示通过可访问公告表达，但不重复打断用户；
- 颜色不是唯一状态信号，选中、错误和破坏性操作同时使用文字或语义；V0.4 不再存在构思集固定容量或“已满”状态；
- 小票打印动画层为装饰并从可访问性树隐藏；成功公告只发出一次，焦点不在打印中间帧间跳动；
- 小票缩略图提供标题/轮次、已保存状态与“双击查看完整小票”提示；进入全屏后焦点移动到票头，退出后回到原缩略图或索引条目；
- 全屏小票以票头、统计、时间线、正文与附件分区建立标题语义；最大辅助字号通过纵向滚动完整承载，不以缩小正文或裁切票尾换取单屏展示；
- “减少动态效果”关闭物理打印、放大和弹性，但不隐藏生成结果；“减少透明度”只替换提示与控制层材质，不改变小票几何、顺序、命中区或行为。

动效阻尼、惯性、速度与取消手感，最大辅助字号下的实际重排，以及 VoiceOver 焦点连续性，均不能通过静态图片或文字参数完成体验确认。本规格冻结可观察结果、失败边界和等价入口；实现起始参数与开发后运行验收按工程基线 `AC-V04-06` 执行，由用户在实际构建中确认体验。
