# ADR-004：收敛到 V0.2 单一活跃代码路径

## 状态

已接受

## 日期

2026-08-08

## 背景

NOTE1 的正式入口已经长期使用 `V02AppShellView`、`V02Store` 和 `V02DomainEngine`，但工程仍同时编译 V0.1 页面、`NoteStore`、旧测试和只连接旧外壳的系统入口。这导致修复可能落在错误实现、两套术语继续漂移，也让测试数量掩盖了当前产品路径的真实覆盖范围。

V0.1 产品与运行事实已经由 `v0.1.0` 标签、冻结 PRD 和历史证据保存；当前 V0.2 业务规则、页面入口、持久化、备份恢复和非回归能力已有独立实现与自动化覆盖。

## 决策

1. 正式 App target 只保留 V0.2 活跃代码路径：`NOTE1App` → `V02AppShellView` → `V02Store` / `V02DomainEngine`。
2. 从正式 target 删除未被 V0.2 入口引用的 V0.1 页面、`NoteStore`、旧备份服务和对应测试；V0.1 历史事实继续由 Git 标签和文档保存。
3. 共享附件来源面板、照片导入和 Quick Look 能力提取到 `AttachmentSupport.swift`，不得因删除旧页面而丢失。
4. V0.2 持久化错误使用 `StoreError`，业务规则错误继续使用 `V02DomainError`。
5. 旧 `AppShortcutSupport` 只向 V0.1 外壳交付草稿，V0.2 外壳从未消费该草稿；继续编译会向系统暴露无法完成闭环的入口，因此从当前 target 移除。未来恢复系统快捷记录时，必须重新连接 V0.2 录入面板并完成真实“快捷指令 → 预填 → 用户确认保存”验收。
6. 治理前本机副本只用于短期交叉审计，不进入 Git；可恢复历史以 Git 标签为准。

## 影响

- 当前工程只有一套可运行产品路径，源码和测试数量显著下降，但不代表删除 V0.2 功能。
- 自动化基线只统计当前 target 中的 V0.2 与共享能力测试；历史测试数字不能继续作为当前结果。
- V0.1 的系统快捷记录不会作为当前可用能力宣传，直至重新完成 V0.2 集成与真机验证。
- 删除后必须通过工程引用扫描、通用设备构建、静态分析、完整 XCTest，以及后续真机非回归验收。

## 未采用的方案

### 继续同时编译两套实现

会保留错误修复落点和术语漂移风险，不采用。

### 只从导航隐藏 V0.1 文件

隐藏不能解决编译边界、死代码和测试口径问题，不采用。

### 把治理前完整工程副本提交进仓库

会复制大量源码并造成新的事实来源；Git 标签已经提供可追溯历史，不采用。
